REFINED HYPOTHESIS (from 01.1-03-SUMMARY.md Open Issue 1, post-ldd diagnostic 2026-05-17):
The original "library compat" hypothesis is FALSIFIED. Operator-side ldd inside the .sif returned ZERO "not found" entries; glibc 2.34 needed vs 2.39 provided (fine); LD_DEBUG=files showed all libraries map and `fini` cleanly, meaning the C++ exception is thrown AFTER all libraries load successfully. So the crash is in Dinamica's OWN startup code after library load. Candidate causes (in order of prior probability):
1. The `cp -a squashfs-root/. . && rm -rf squashfs-root DinamicaEGO.AppImage` step in `.def` `%post` line 88-89 dropped a non-squashfs side asset (e.g. a `Data/GDAL` or `Data/proj` subtree, or a Qt plugins dir).

3. A file that DinamicaConsole tries to read at startup (registry, license file, plugin manifest) that doesn't exist where expected.
4. A `.dinamica_ego_8.conf` key the staged-home copy is missing (the .def seeds only AlternativePathForR + ClConfig + MemoryAllocationPolicy + RCranMirror).

The diagnostic ladder below distinguishes these four hypotheses.
