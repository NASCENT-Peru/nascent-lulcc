# Phase 05.1 Plan 02: Smoke-verifier non-vacuity and mask value-domain guard Summary

Re-sited the Absolute-0 non-vacuity assertion from per-map (where zero cells is ordinary) to
per-intervention and per-run (where zero checked maps is a real defect), added an Outside-zone
mask non-degeneracy proof, and made the CR-01 value-domain stops fatal forbidden markers.

## maps_checked semantics (for plan 05.1-03's operator gate)

`maps_checked` now counts **only those per-transition probability maps that had at least one
non-NA probability cell inside the selected zone** — maps whose transition's from-class does not
intersect the mask in this region print an `Info: ... not counted` line and are excluded, so a
PASS banner's `maps_checked` may legitimately be lower than the number of matching
`trans_rates.csv` rows, while `maps_checked=0` with any active Absolute-0 intervention is now a
hard FAIL.

## What Was Built

### Task 1 — per-map INFO downgrade and re-sited assertion (commit `3a4a3c0`)

`scripts/verify_intervention_smoke.r`, section (c):

- **D-05 / WR-04.** The `if (!is.finite(n_zone) || n_zone == 0) { fail(...); next }` branch is now
  an INFO branch: it prints
  `"  Info: %s %s has no non-NA cells in zone=%s (mask does not intersect this transition's from-class); not counted\n"`,
  does not call `fail()`, does not increment `maps_checked`, and still `next`s. The replaced
  WR-07 comment block now cites `src/allocation.r:3196-3200` as the evidence that `r` is built as
  `setValues(anterior, NA_real_)` with `dt_j$prob` written at `dt_j$cell_id`, so `n_zone` counts
  "cells in the selected zone that also hold this transition's from-class" and zero is ordinary.
  The `!is.finite()` arm stays folded into the same condition.
- **D-06a.** `n_checked_id <- 0L` is initialised immediately before `for (k in rows)` and
  incremented on the line directly after `maps_checked <- maps_checked + 1L`, so the two cannot
  diverge. After the map loop closes (still inside `for (x in abs0)`), `n_checked_id == 0L` calls
  `fail()` with the frozen message
  `"%s: no probability map could be asserted on (0 of %d target map(s) had a non-NA probability cell in zone=%s for mask %s)"`.
- **D-06b.** The `if (maps_checked == 0L) { cat("Info: no Absolute-0 target maps present ...") }`
  block became a `fail()` with
  `"maps_checked=0: no Absolute-0 probability map could be asserted on in this region, but %d active Absolute-0 intervention(s) are configured"`.
  The block is already inside `if (length(abs0) > 0L)`, so the guard is structural.
- File-level roxygen bullet (c) rewritten as the three-level contract (per map INFO / per
  intervention FAIL / per run FAIL). The old sentence claiming an empty zone "is a FAIL and is NOT
  counted in maps_checked ... (WR-07)" is gone.

The PASS banner format string, the `[ok]`/`FAIL` per-map status line, the non-finite-`mx` branch
and sections (a), (b), (d), (e) are untouched.

### Task 2 — Outside non-degeneracy and the CR-01 markers (commit `f6bdff1`)

- **D-04.** `degeneracy_checked <- FALSE` is initialised next to `n_checked_id`. Immediately after
  `sel` is built, a `zone == "Outside" && !degeneracy_checked` branch sets the flag, computes
  `n_ones <- terra::global(m0 == 1, "sum", na.rm = TRUE)[[1]][1]` and, when that is non-finite or
  zero, calls `fail()` with the frozen `degenerate mask` message. It does **not** `next` — the
  ordinary max-probability assertion still runs. Only the `Outside` branch needs it: for `Inside`,
  `sel` IS `m0 == 1`, so a degenerate mask already produces `n_zone == 0` on every map and is
  caught by D-06a.
- **D-03.** Two entries appended to the `forbidden` vector under a section comment naming plan
  05.1-01 and CR-01: the literal strings `outside {0,1,NA}` and `is categorical/non-numeric`.
  Matching is `grep(f, lines_p, fixed = TRUE)`, so the braces are literal. A repo-wide grep before
  adding them confirmed neither substring appears on any success line — the only pre-existing
  occurrence is a `FAIL` message in `scripts/validate_intervention_masks.r:271`, a different
  script the smoke verifier does not scan.
- Added one roxygen sentence to bullet (c) recording the Outside non-degeneracy requirement, so
  the documented contract matches the implemented one.
