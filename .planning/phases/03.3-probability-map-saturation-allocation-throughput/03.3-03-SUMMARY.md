# Phase 03.3 Plan 03: Standalone Saturation Diagnostic CLI Summary

## Outcome

Created `scripts/diagnose_allocation_saturation.r`, a standalone post-hoc diagnostic CLI for allocation work directories. The script reads `trans_rates.csv`, `anterior.tif`, `posterior.tif`, and `probability_map_dir/`, reuses `compute_per_transition_metrics()` from `src/saturation_diagnostics.r`, writes `saturation_diagnosis.csv`, and prints a compact operator-facing summary.

The CLI supports:

```text
Rscript scripts/diagnose_allocation_saturation.r <work_dir>
Rscript scripts/diagnose_allocation_saturation.r <work_dir> --dinamica-log <log_path>
```

## Implementation

The script follows the seven-section structure required by the plan:

1. Shebang and Roxygen-style usage header.
2. Project-root sniff and `setwd(project_root)` copied from `scripts/run_allocation.r`.
3. Ordered source list: `src/setup.r`, `src/utils.r`, `src/saturation_diagnostics.r`.
4. Argument parsing and artifact validation.
5. Main diagnosis logic with shared metric-helper reuse.
6. Output write plus console summary.
7. Explicit `quit(status = 0L)`.

The output `saturation_class` column is derived as exactly one of `aligned_ok`, `saturation_bound`, or `exempt`. When `--dinamica-log` is supplied, the script parses the Dinamica Remaining-Transitions matrix and adds `remaining_cells` plus `dinamica_log_drift` for cross-validation.
