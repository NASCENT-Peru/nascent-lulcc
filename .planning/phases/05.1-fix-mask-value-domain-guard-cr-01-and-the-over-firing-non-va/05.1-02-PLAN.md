<objective>
Close WR-04 and the verifier half of CR-01.

WR-04: `r` is a *per-transition* probability map, non-NA only on that transition's from-class
cells (`src/allocation.r:3196-3200` builds it as `setValues(anterior, NA_real_)` then writes
`dt_j$prob` at `dt_j$cell_id`). So `n_zone == 0` — "cells inside the selected zone that also hold
this one transition's from-class" — is an ordinary, correct-engine outcome. NAT's
`Absolute`/`0`/`Inside` entry targets three To classes, so rare from-classes are routinely checked;
a protected-area mask holding no `low_intensity_agricultural_areas` cells in `andes` makes
`low_intensity_ag -> mining` report `n_zone = 0`. Today's guard (added as WR-07 in plan 05-14)
calls `fail()` there and exits 1 on a perfect run. It converted a false PASS into a false FAIL.
It has not been seen yet only because the one gated combination (NAT x costa_peruana x 2032,
`maps_checked=16`) happens not to trigger it.

CR-01 (verifier half): the `Outside` assertion is trivially satisfied by an all-zero mask, so the
shipped evidence for Phase 5 cannot distinguish "the mining mask is correctly 1-coded" from "the
mining mask reads as empty". D-04 makes the verifier prove the mask is non-degenerate; D-03 makes
the engine's new value-domain stops fatal markers here too.

Purpose: the verifier must fail exactly when the engine is wrong, and only then.
Output: a restructured Absolute-0 section with the assertion re-sited two levels up, plus fixtures
proving both directions.
</objective>
