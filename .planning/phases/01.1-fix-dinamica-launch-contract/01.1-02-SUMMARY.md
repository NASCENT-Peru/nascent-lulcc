## Accomplishments

- `scripts/smoke_test_dinamica.sh` LAUNCH_CMD array now uses the D-104 shape: `apptainer exec --home $STAGED_HOME --env DINAMICA_EGO_8_TEMP_DIR=$STAGED_TMP $ARTIFACT bash -c 'cd /opt/dinamica/usr && bin/DinamicaEGO.sh <abs-model>'`. - `STAGED_HOME` / `STAGED_TMP` (under `$HPC_SCRATCH_ROOT`) and `ABS_EGO_MODEL` (via `readlink -f` with python3 fallback) are resolved before LAUNCH_CMD; `--live` fails fast (exit 1) with a named-signal message if `HPC_SCRATCH_ROOT` is unset; `--dry-run` tolerates a missing `HPC_SCRATCH_ROOT` by using `$TMPDIR` so workstation operators can still print the launch plan.

On HPC detection without `HPC_SCRATCH_ROOT`, the script exits 1 with a named-signal message ("HPC context detected (<signal>) but HPC_SCRATCH_ROOT is unset"); on a workstation it keeps the `.envs` path and emits the line "Env install root (local fallback, no HPC signals): ...".
- New `tests/shell/test-setup-environments-hpc-refusal.sh` (128 lines, executable) runs end-to-end on a vanilla bash host with no R / Dinamica / apptainer / micromamba required, asserting all 5 cases pass (`PASS: 5  FAIL: 0`).

## Decisions Made

1. **Moved the HPC_SCRATCH_ROOT check for `--live` mode in `smoke_test_dinamica.sh` to BEFORE the runtime probe.** The plan's Step C placed the staged-home resolution AFTER the runtime probe, but the plan's explicit acceptance criterion required `--live` without `HPC_SCRATCH_ROOT` to exit with code **1** and stderr containing "requires HPC_SCRATCH_ROOT". On a Windows host without apptainer the runtime probe fires first and exits **2** with a different message, which would have failed the acceptance criterion. The fix adds an early HPC_SCRATCH_ROOT guard (just after argument validation) that handles only the `--live` + missing-var case; the later block at the original position now handles only the `--dry-run` tempdir fallback. The acceptance criterion now passes verbatim.
2. **Test harness uses `MAMBA_EXE_CUSTOM` rather than PATH-only stubbing.** The plan's Task 2 Step A "Recommended: (a) PATH-stubbing" assumed micromamba is resolved via PATH, but `scripts/hpc_common.sh:find_micromamba` (lines 61–93) explicitly does NOT consult PATH — it only checks `MAMBA_EXE_CUSTOM`, `$HOME/.local/bin/micromamba`, and `/cluster/home/$USER/.local/bin/micromamba`. Using `MAMBA_EXE_CUSTOM` (the documented operator override) keeps the test harness aligned with the production code path and avoids introducing a test-only hook in the production script.
3. **`run_case()` passes `USER` and `MAMBA_EXE_CUSTOM` explicitly through `env -i`.** Without `USER`, `hpc_common.sh` line 67 fails under `set -u` with "USER: unbound variable" before any HPC detection runs.
