## What changed

### `scripts/verify_intervention_smoke.r`

- **Region grid reference** established once inside section (c), before the intervention
  loop, from the first `.tif` in `probability_map_dir`. Every per-transition map in a
  region is `terra::setValues(anterior, ...)`, so all share one geometry — the old code
  already relied on this when it latched D-04 on the first map it happened to visit.
- **D-04 hoisted** out of the per-map loop to directly after `m_nat <- terra::rast(mask_path)`
  and above `rows <- which(...)`. The `degeneracy_checked` latch is gone from the file.
  The proof crops the mask to `region_ref`, re-uses the existing
  `mask %s does not align with %s after crop (no resampling allowed)` wording on a geometry
  mismatch, and emits the byte-identical degenerate-mask message otherwise. It does not
  `next` — the rest of the intervention still runs.
- **`unasserted_ids` ledger** appended on the `length(rows) == 0L` skip path and checked
  after the intervention loop, before the D-06b floor. D-06a ids are deliberately NOT
  added (it already `fail()`s naming them).
- **`judged_log_lines`** declared next to `iv_lines` and assigned in the section (b)
  else-branch, so section (c) judges the same log section (b) judged.
- **Empty-map discrimination** inside the `n_zone == 0` branch: `n_r` (non-NA cells
  anywhere) is computed only there, so the happy path pays nothing. `n_r == 0` with the
  engine WARN present is INFO and not counted; without it, a FAIL. `n_r > 0` keeps today's
  INFO wording and behaviour exactly.
- **Forbidden scan de-duplicated** with a per-log `reported` vector of already-reported
  line texts. "At most one error per marker" is preserved, so the count stays bounded by
  `length(forbidden)`.
- **Roxygen contract corrected** in bullets (c) and (d) so no statement is stronger than
  the code; the false "that case is caught run-level by D-06b" comment is gone.

### `tests/testthat/test-verify-intervention-smoke.R`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `utils::modifyList()` silently dropped unnamed list overrides in the `second` fixture field**

- **Found during:** Task 3 (first test run: the GAP-1 control block failed with
  `Info: iv_mine has no target rows` despite passing `targets = list("built_up_and_barren_lands", "high_intensity_agricultural_areas")`)
- **Issue:** `modifyList()` recurses into list-valued fields and merges them BY NAME. For
  an unnamed override list it iterates `names(val)`, which is `NULL`, so it returns the
  DEFAULT `list("mining")` unchanged. The control fixture therefore built a mining-only
  second intervention and could never have exercised the two-rows path.
- **Fix:** replaced the merge with wholesale per-field replacement
  (`for (nm in names(second)) sec[[nm]] <- second[[nm]]`), with a comment stating why
  `modifyList()` is wrong here.
- **Files modified:** `tests/testthat/test-verify-intervention-smoke.R`
- **Commit:** `280c8a0`

**2. [Rule 1 - Bug] The plan's fixture spec for the GAP-1 control was internally inconsistent**

- **Found during:** Task 3 (observed `ERROR: iv_mine: telemetry sum(sum_abs_delta)=3.24 differs from AUDIT sum_abs_delta=1.62`)
- **Issue:** the plan routes the single `second$sum_abs_delta` field to BOTH the AUDIT line
  (where it is the intervention total) and `.smoke_telemetry()` (where it is the
  per-target-class vector). With the plan's literal `sum_abs_delta = 1.62` the two rows get
  `1.62` each, summing to `3.24`, and section (e)'s reconciliation correctly rejects the
  fixture. The same field cannot carry both meanings.
- **Fix:** the field is now the per-telemetry-row vector and the builder passes
  `sum(sec$sum_abs_delta)` to the AUDIT line. The control block passes
  `sum_abs_delta = c(1.2, 0.42)`, whose sum is the `1.62` the plan intended on the AUDIT
  line. The default `second` (`sum_abs_delta = 0`) is unaffected: `sum(0) == 0`.
- **Files modified:** `tests/testthat/test-verify-intervention-smoke.R`
- **Commit:** `280c8a0`

**3. [Rule 3 - Blocking] `^\\s*#` in the plan's verify commands could not survive this shell**

- **Found during:** Tasks 1 and 2
- **Issue:** the plan's `<automated>` checks are single-line `Rscript -e '...'` invocations
  containing `^\\s*#`. Git Bash on this host mangled the backslash escaping, producing
  `Error: '\s' is an unrecognized escape in character string`.
- **Fix:** the identical assertions were run from script files in the session scratchpad
  using the POSIX-class equivalent `^[[:space:]]*#`. Same semantics, same assertion set,
  same `ok` output. No change to any repository file.
- **Files modified:** none
- **Commit:** n/a
