**Resume signal received:** `partial: 2-3 failed`

**Step 2 root cause:** `strings` produced no output — binary likely uses compressed string tables or
the command failed silently inside the container.

**Step 3 root cause:** Euler HPC has `/proc/sys/kernel/yama/ptrace_scope` set restrictively
(likely `1` or `2`); both in-container strace and host-attach attempts were blocked. No unprivileged
ptrace access available without root or a ptrace-unrestricted compute node.

## Hypothesis Ranking (from FINDINGS.md)

| Hypothesis | Description | Status |
|------------|-------------|--------|
| H1 | `cp -a squashfs-root/. . && rm -rf` dropped Data/ subtree | **FALSIFIED** |
| H2 | Missing `DINAMICA_EGO_8_*` env var | **INCONCLUSIVE** |
| H3 | Specific file fails to open at startup | **UNVERIFIED** (ptrace blocked) |
| H4 | Missing `.dinamica_ego_8.conf` key | **UNVERIFIED — PLAUSIBLE** |

### Key finding for H1
`extract-diff.log` contains zero `<` lines — nothing was dropped from the AppImage by the
`cp -a + rm -rf` sequence in `%post`. `ls-data-tree.log` confirms `Data/GDAL` (proj.db, full GRIB2
tables, cmake modules) and `Data/R` (Dinamica_1.0.8.tar.gz) are intact inside the `.sif`.

### Key finding for H2
Cross-evidence from `01.1-03-SUMMARY.md` lines 115–116 (wrapper with `.ego` → same crash as bare
`DinamicaConsole`) weakens H2 for vars the wrapper sets. However, env vars that must be present
at container-level (before the wrapper runs) remain untested. Current `%environment` block is
missing `DINAMICA_EGO_8_GDAL_DATA` and `DINAMICA_EGO_8_LOG_PATH`.

### Key finding for H4
`%post` Stage 5 seeds only four conf keys (AlternativePathForR, ClConfig, MemoryAllocationPolicy,
RCranMirror). Path-related keys (`PathForGDALData`, `PathForRData`) are absent. The GUI mode works
(`DinamicaEGO.sh` without `.ego`) while console mode does not — this asymmetry is consistent with
H4 if console mode reads a conf key that GUI mode does not need.

## Evidence Sufficiency for Plan 06

**The evidence is sufficient to direct Plan 06 to a concrete fix attempt, but Plan 06 must include
its own re-verify-and-iterate gate** because the two most diagnostic steps (strings, strace) were
blocked, leaving H2 and H4 INCONCLUSIVE/PLAUSIBLE rather than CONFIRMED.

Plan 06's two-sub-step approach (see `diagnostics/FINDINGS.md` Proposed Fix section):

1. **Sub-step A (read-only diagnostic):** `apptainer exec "$DINAMICA_EGO_8_HOME" cat /opt/dinamica/usr/bin/DinamicaEGO.sh`
   — determines whether the wrapper exports `DINAMICA_EGO_8_GDAL_DATA` / `DINAMICA_EGO_8_LOG_PATH`
   before calling `DinamicaConsole`. Result routes to B1 or B2.

2. **Sub-step B1 (H2 fix):** Add `export DINAMICA_EGO_8_GDAL_DATA=/opt/dinamica/usr/bin/Data/GDAL`
   and `export DINAMICA_EGO_8_LOG_PATH=/tmp/dinamica` to `%environment` in
   `dinamica/container/rocker-geospatial-dinamica.def` (current lines 112–118).

3. **Sub-step B2 (H4 fix):** Extend `%post` Stage 5 conf seed (current lines 97–104) with
   `PathForGDALData = "/opt/dinamica/usr/bin/Data/GDAL"` and
   `PathForRData = "/opt/dinamica/usr/bin/Data/R"`. Also add to
   `src/dinamica_utils.r:resolve_dinamica_launch()` HPC branch conf seeder.
