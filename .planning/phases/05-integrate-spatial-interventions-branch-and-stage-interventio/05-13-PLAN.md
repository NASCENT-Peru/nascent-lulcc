<objective>
Implement the CSV half of the probability-change telemetry requirement (D-18) and its non-fatal
write and pre-flight rules (D-21): a per-intervention x per-target-class
`intervention_prob_deltas_<scenario>_<region>_<year>.csv` written alongside the run outputs.

Purpose: the AUDIT line carries a roll-up per intervention; scenario review needs the per-class
detail as a table it can load, and it must never be able to kill a run that would otherwise succeed.

Output: a sanitised, atomically-renamed, non-fatal CSV writer wired to the allocation hook, plus a
Stage 7 pre-flight check that an unwritable output root is reported before the run starts.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scenario name and region label -> output filename | Config-supplied strings are interpolated into a filesystem path |
| telemetry write -> run success | A new write path inside a multi-hour worker must not become a new failure mode |
| region work directory -> run outputs | The CSV is written next to `posterior.tif`, `trans_rates.csv` and `probability_map_dir` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-47 | Tampering | Directory traversal via scenario / region in the CSV filename | mitigate | Region is slugged then both tokens pass `gsub("[^A-Za-z0-9_.-]", "_", x)`; the composed basename is asserted free of `/`, `\` and `..` before any write, and a violation raises inside the tryCatch (Task 2) |
| T-05-48 | Denial of service | Unwritable or malformed telemetry path aborting a multi-hour run | mitigate | The write is wrapped in `tryCatch` and degrades to a `WARN intervention telemetry:` log line; the Stage 7 pre-flight reports an unwritable output root before any work starts (D-21) |
| T-05-49 | Tampering | Partially written CSV read as complete | mitigate | `data.table::fwrite()` to a `.tmp` path followed by `file.rename()`, mirroring `write_raster_atomic()`; the `.tmp` is removed on failure |
| T-05-50 | Tampering | Clobbering an existing run's telemetry | accept | The filename is keyed on scenario, region and year inside the region work directory, so a re-run overwrites its own output exactly as `posterior.tif` already does; recorded rather than mitigated |
| T-05-SC | Tampering | package-manager installs | n/a | `data.table` is already a declared dependency; no `install.packages`, npm, pip or cargo invocation appears in any task |
</threat_model>
