# Phase 05.1 Plan 05: Stage 7 mask value scan Summary

**The Stage 7 pre-flight now proves the real `{0,1,NA}` predicate with one non-rounding `terra::freq()` scan per unique mask instead of proving its min/max envelope, so an all-zero mask and an all-0.5 mask are rejected before any region work, an unreadable value block is a hard stop rather than "nothing to report", and a mask with two independent defects reports both.**

## Performance

- **Duration:** ~55 min
- **Tasks:** 3 of 3
- **Files modified:** 4
- **Commits:** 3 (plus this metadata commit)

## Accomplishments

- Replaced `!(mm[1] >= 0 && mm[2] <= 1)` with a single `terra::freq(m, digits = 12)` scan. The envelope test passed an all-`0.5` mask (GAP-3 / R51-WR-02, which then hard-stopped hours later inside the first region) and an all-zero mask (GAP-2 / R51-WR-01, whose all-FALSE lookup made a `Prob_adjust_zone: Outside` zone the whole region — the exact impact this phase exists to prevent). Both are now rejected at Stage 7.
- Made both swallowed `tryCatch` handlers hard stops (R51-WR-03): the `is.factor` probe now returns the condition message instead of `FALSE`, and the value scan reports `values could not be read` instead of degrading to `c(NaN, NaN)`. The all-NA tolerance survives, carried by the empty-`vals` branch.
- Replaced the four `next`s with a per-mask accumulator (R51-IN-04), so a 255-coded mask on a shifted grid reports two lines instead of one.
- Added seven pre-flight fixtures and strengthened the existing all-NA block; three of the new fixtures were mutation-checked against the implementation.
- Corrected the two operator documents, including the deliberate all-NA silence (so an operator does not read it as a missed check) and the two new smoke-verifier hard FAILs that plan 05.1-04 introduces.

## Required Output (a): the exact pre-flight message formats

Verbatim `sprintf` format strings as they now stand in `src/allocation.r`. Plan 05.1-07's contract test consumes these.

1. Out-of-domain (D-03 frozen prefix + frozen `outside {0,1,NA}`; the parenthetical is new):

```r
"intervention mask: %s has value(s) outside {0,1,NA} (observed min %s, max %s; %d distinct bad value(s))"
```
Arguments: `mask_path`, `format(min(vals))`, `format(max(vals))`, `length(bad)`.

2. No cell equal to 1 — the COLON form (plan 05.1-06 emits the colon-free form from the engine):

```r
"intervention mask: %s has no cell equal to 1 (every non-NA cell is 0); the Inside zone is empty and the Outside zone is the whole region"
```
Argument: `mask_path`. Held in ONE contiguous string literal.

3. Values could not be read — **freq branch**:

```r
"intervention mask: %s values could not be read (%s)"
```
Arguments: `mask_path`, then `conditionMessage(fq)` when `inherits(fq, "error")`, otherwise the literal `unexpected freq shape` (covers `!is.data.frame(fq)` and a table missing `value`/`count`).

4. Values could not be read — **is.factor branch** (byte-identical format, different source):

```r
"intervention mask: %s values could not be read (%s)"
```
Arguments: `mask_path`, `conditionMessage(e)` from the raised `terra::is.factor(m)` probe.

Unchanged and byte-identical to HEAD: `"intervention mask: unreadable %s (%s)"`, `"intervention mask: %s has %d layers (expected 1)"`, `"intervention mask: %s is categorical/non-numeric; expected numeric {0,1,NA}"`, `"intervention mask: %s is not on the reference grid (crs/res/extent mismatch)"`.

## Decisions Made

- **Block 4b naming.** The plan's `<verify><automated>` asserts `sum(grepl("R51-WR-03", r$test)) == 2`, while its `<acceptance_criteria>` prose says three blocks carry that id — an internal contradiction. The executable verify was treated as authoritative, so the is.factor-half block is named `REVIEW WR-03 (is.factor half): ...`. It is unambiguous (REVIEW = `05.1-REVIEW.md`) and does not contain the `R51-WR-03` substring.
- **`NULL` as the body of the empty-`vals` branch.** The branch must exist and must be ordered first, but must append nothing. An explicit `NULL` no-op keeps the ordering visible (and greppable by the plan's verify) rather than inverting the condition.
- **Mock scoping.** Both mask-level mocks match on `terra::sources(x)` and delegate everything else to the binding captured before the mock was installed, because terra calls `is.factor()` and `freq()` internally.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The is.factor-half fixture was vacuous as specified**
- **Found during:** Task 2, while running the mutation check the plan's own acceptance criteria require
- **Issue:** The plan specified block 4b as "mock `terra::is.factor` to raise over an otherwise valid mask, so the ONLY reason a line appears is the raised is.factor call". That is not true: `terra::freq()` calls `is.factor()` on the SpatRaster internally, so with the implementation mutated back to the swallowing `error = function(e) FALSE` handler the mask was still reported as `values could not be read` — via the *freq* handler, with textually identical output. The block stayed green under the mutation it is supposed to catch.
- **Fix:** stub `freq` to a well-formed all-1 `data.frame` in the same `local_mocked_bindings()` call, removing the alternative emission path. The block then fails under mutation 3 and the reason for the stub is stated in a comment.
- **Files modified:** `tests/testthat/test-spatial-interventions-wiring.R`
- **Verification:** mutation 3 re-applied → 1 failure in that block; restored → 50 tests / 184 expectations / 0 failures.
- **Committed in:** `7c9a93b`

**2. [Rule 3 - Blocking] An unconditional `is.factor` mock raises inside terra itself**
- **Found during:** Task 2, first run of the new blocks
- **Issue:** `testthat::local_mocked_bindings(is.factor = function(x, ...) stop(...), .package = "terra")` as written in the plan produced an uncaught `Error in is.factor(values): mocked is.factor failure` and errored the test block — terra calls `is.factor()` internally on plain vectors, outside the pre-flight's `tryCatch`.
- **Fix:** scope the mock exactly as the plan already scopes the `freq` mock in block 3 — raise only for a `SpatRaster` whose `terra::sources()` names a staged mask, delegate everything else to the pre-mock binding.
- **Files modified:** `tests/testthat/test-spatial-interventions-wiring.R`
- **Verification:** block runs clean; mutation 3 still turns it red.
- **Committed in:** `7c9a93b`

**3. [Rule 3 - Blocking] `Rscript -e` on this host strips one backslash level**
- **Found during:** Task 1, running the plan's automated verify
- **Issue:** the verify command's `readLines(...); body <- src[!grepl("^\\s*#", src)]` reached R as `"^\s*#"` and failed with `'\s' is an unrecognized escape`. This is argument-quoting on Windows/Git Bash, not a code defect.
- **Fix:** ran the identical assertions from a script file with the POSIX class `^[[:space:]]*#`, which is semantically identical to `^\s*#` for this purpose. All assertions in the plan's verify were executed unchanged otherwise, and all passed (`ok`).
- **Files modified:** none (tooling only)
- **Verification:** `ok` printed; the same approach was used for the task 2 and task 3 verifies, both of which also printed `ok`.
- **Committed in:** n/a
