# Phase 3.2 Validation Architecture

## Validation Strategy

Phase 3.2 is a pipeline observability and consistency phase — it adds structured AUDIT log lines, moves hardcoded config into YAML, fixes a crash bug, promotes a warning to a stop(), and creates a cross-stage audit script. It does NOT add new data transformations, business logic, or ML models.

**Verification approach: parse-only (intentional)**

Full behavioral testing of this phase requires running the complete 7-stage LULCC pipeline with real Peruvian raster data on ETH Euler HPC (≥1h wall time, licensed data not in the repository). Unit testing with synthetic fixtures is structurally possible but was deferred (see Wave 0 gaps below) because:
1. All changes are additive (log lines, config keys, a new stop()) — they cannot silently corrupt existing behavior; they either succeed or fail fast.
2. The cross-stage audit script (Plan 03.2-03) serves as the integration verification — it reads real pipeline artifacts and exits 1 on any set difference.
3. The operator HPC smoke run (inherited gate from Phase 3.1 SC-3) is the behavioral gate for the full pipeline.

**Accepted minimum per task:** `Rscript -e "source('file.r')"` parse check + `grep` pattern verification of inserted log/stop lines.
