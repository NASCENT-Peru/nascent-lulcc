## Summary

Scope: the non-`.planning` diff of `3901234..HEAD` — D-01 (`.mask_inside_lut()` value domain),
D-02/D-02b (Stage 7 pre-flight rejection in `validate_allocation_runtime()`), D-03 (forbidden
markers), D-04 (Outside non-degeneracy), D-05/D-06 (re-sited non-vacuity), and the three test
files. No `CLAUDE.md` and no skill packs exist in the repo; the JS/TS convention rule packs
return `findings: []` for `.R`/`.r` (no pack for this language), so there are no CONVENTION-tier
findings from tooling.

What holds up under adversarial testing (verified, not assumed, on terra 1.9.34):

- `terra::minmax(m, compute = TRUE)` really does return `NaN NaN` for an all-NA raster, and
  `as.vector()` of it really is length 2, so `all(is.finite(mm))` in `src/allocation.r:684` is
  genuinely load-bearing: without it the guard would throw the forbidden marker
  `"missing value where TRUE/FALSE needed"`. Confirmed empirically.
- The categorical detection is consistent across the two halves on this terra version:
  `terra::is.factor()` is `TRUE` exactly when `terra::extract()` round-trips a `factor`, so the
  pre-flight branch and the engine's `!is.numeric(v)` branch fire on the same inputs. (See IN-02
  for the durability concern, not a current defect.)
- The frozen substrings `outside {0,1,NA}` and `is categorical/non-numeric` survive both
  `sprintf()` formats intact (all placeholders are `%s`, the braces are literal, the verifier
  matches `fixed = TRUE`); drift in either file currently breaks a test (see IN-05 for the gap).
- The specific suspicion that `degeneracy_checked` is scoped too widely is **unfounded**: it is
  re-initialised at `scripts/verify_intervention_smoke.r:346`, inside the per-intervention loop,
  so two Outside interventions with different masks each get their own check. The real hole is
  one level up, and it is CR-01 below.

What does not hold up: the verifier can still print `PASS` while an entire Absolute-0 Outside
intervention with a degenerate mask was never asserted on (CR-01, reproduced, exit status 0),
and the two engine-side guards still let the exact CR-01 impact (an all-FALSE LUT inverting
`Prob_adjust_zone: Outside` onto a whole region) through for an all-zero mask (WR-01), while the
pre-flight's range test cannot see in-range non-`{0,1}` values at all (WR-02, reproduced).

## Critical Issues

### CR-01: The verifier reports PASS on a run in which an Outside intervention with a degenerate mask was never asserted on

**File:** `scripts/verify_intervention_smoke.r:333-336` (the `length(rows) == 0L` → `next`
path), interacting with `scripts/verify_intervention_smoke.r:341-346`, `:373-384` (D-04),
`:431-436` (D-06a) and `:445-450` (D-06b)

**Issue:** D-06a (`n_checked_id == 0L`) and D-04 (Outside non-degeneracy) both live *after* the
`length(rows) == 0L` early `next`, and D-06b's floor is `maps_checked == 0L` — a **run-level**
counter shared by every Absolute-0 intervention. So when a run has two or more active Absolute-0
interventions and one of them has no matching rows in `trans_rates.csv`, that intervention is
skipped with a one-line `Info:` and **nothing** about it is asserted: not its mask's
non-degeneracy, not a single probability map — while the other intervention keeps
`maps_checked > 0`, so D-06b never fires and the script exits 0.

The code comment at `:437-442` states this case "is caught run-level by D-06b". That is only
true when *every* active Absolute-0 intervention lacks rows. The header contract at
`:25-27` ("per intervention: zero checked maps is a FAIL") is likewise stronger than the code.
`tests/testthat/test-verify-intervention-smoke.R:348-357` (D-06b) and `:359-369` (D-04) pin only the single-intervention
shape, which is why the hole is untested.

This is exactly the shipped configuration shape, not a hypothetical: `config/NAT_interventions.yml`
has `Conservation_expansion_and_preservation` (Absolute/0/**Inside**, three target classes, so
it almost always has rows) and `Mining_freeze_post_2030` (Absolute/0/**Outside**, target class
`mining` only, from 2032). A region whose `trans_rates.csv` holds no `* -> mining` row — common,
mining transitions are rare and region-specific — produces a green `PASS ... maps_checked=2`
banner that is read as evidence for both interventions while the mining freeze, the one whose
degenerate-mask inversion CR-01 exists to catch, was never looked at.

Reproduced against the real script (two-intervention fixture: `iv_abs` Inside with a correct
mask and rows; `iv_mine` Outside with an **all-zero** mask and no matching `To_lulc` row;
AUDIT lines and 25-column telemetry present for both so sections (b)/(e) pass):

```
  iv_abs zone=Inside 001_id_trans_11.tif: n_zone=3 max prob in zone = 0 [ok]
  iv_abs zone=Inside 002_id_trans_12.tif: n_zone=3 max prob in zone = 0 [ok]
Info: iv_mine has no target rows in trans_rates.csv for this region
telemetry: 3 rows, 2 interventions, 3 classes [ok]
PASS verify_intervention_smoke scenario=BAU region=r1 year=2028 interventions=2 maps_checked=2 telemetry_rows=3
=== EXIT STATUS: 0 ===
```

**Fix:** make the per-intervention ledger cover the skip path, and move the mask-degeneracy
proof off the map loop so it runs for every Outside intervention regardless of `rows`:

```r
      # before the abs0 loop
      unasserted_ids <- character(0)
      for (x in abs0) {
        ...
        m_nat <- terra::rast(mask_path)
        # D-04: the mask's own non-degeneracy does not depend on trans_rates.csv,
        # so prove it BEFORE the no-target-rows escape. Crop to the region map
        # only if one exists; otherwise assert on the national mask.
        if (identical(zone, "Outside")) {
          n_ones <- terra::global(terra::ifel(is.na(m_nat), 0, m_nat) == 1,
                                  "sum", na.rm = TRUE)[[1]][1]
          if (!is.finite(n_ones) || n_ones == 0) {
            fail(sprintf("%s: mask %s has 0 cells equal to 1 ...", id, basename(mask_path)))
          }
        }
        rows <- which(...)
        if (length(rows) == 0L) {
          unasserted_ids <- c(unasserted_ids, id)   # not silently fine
          cat(sprintf("Info: %s has no target rows in trans_rates.csv for this region\n", id))
          next
        }
        ...
        if (n_checked_id == 0L) { fail(...) }
      }
      # run-level: every active Absolute-0 intervention must have been asserted on
      if (length(unasserted_ids) > 0L) {
        fail(sprintf(
          "no probability map could be asserted on for active Absolute-0 intervention(s) %s (no target rows in trans_rates.csv for this region); this run is not evidence for them",
          paste(unasserted_ids, collapse = ", ")
        ))
      }
      if (maps_checked == 0L) { fail(...) }   # keep as the floor
```

Add a regression test with two Absolute-0 entries, the second Outside/no-rows/degenerate-mask,
expecting status 1 — the current suite has no multi-intervention Absolute-0 fixture at all.

## Warnings

### WR-01: An all-zero mask still produces the all-FALSE LUT inversion, silently, through both new guards

**File:** `src/allocation.r:680-694` (pre-flight range test) and
`src/implement_spatial_interventions.R:327-350` (engine guard)

**Issue:** the phase's stated impact statement is "an all-FALSE LUT inverts the policy onto the
whole region and silently zeroes every `* -> mining` probability from 2032". The new guards close
that for `255` and for categorical masks, but an **all-zero** mask (a `gdal_rasterize` that burned
nothing, a mask clipped to the wrong AOI, a mask whose polygons missed the grid) has value domain
`{0}` ⊂ `{0,1,NA}`: `minmax` is `0 0`, which satisfies `mm[1] >= 0 && mm[2] <= 1`, and the engine's
`bad` set is empty. Verified end to end:

```
all-zero mask: no error. LUT = FALSE FALSE FALSE FALSE FALSE FALSE
  -> zone Outside selects 6 of 6 region cells
```

and `implement_spatial_interventions.R:1053-1060` then takes `sub_idx[!inside_flag]`, i.e. the
whole region, with no WARN line anywhere. The all-NA variant is a documented, deliberate
exclusion (`src/allocation.r:669-679`) delegated to the verifier's D-04 — but D-04 is a
*smoke-script, single-region, Outside-only* check, and per CR-01 it can be skipped entirely, so
production runs have no coverage for either variant. The all-zero variant is not mentioned in any
comment or decision.

**Fix:** `mm` is already in hand, so the all-zero case costs zero extra I/O — a mask with
`max != 1` has no "inside" cell at all and cannot express either zone:

```r
              if (length(mm) == 2L && all(is.finite(mm)) && mm[2] != 1) {
                intervention_errors <- c(
                  intervention_errors,
                  sprintf(
                    "intervention mask: %s has no cell equal to 1 (observed min %s, max %s); the Inside zone is empty and the Outside zone is the whole region",
                    mask_path, format(mm[1]), format(mm[2])
                  )
                )
                next
              }
```

(Prefer folding this into the single `terra::freq()` scan proposed in WR-02, which closes WR-01
and WR-02 together.)

### WR-02: The pre-flight range test cannot see in-range non-{0,1} values, so the gate it is meant to be is incomplete

**File:** `src/allocation.r:680-694`

**Issue:** the block's own rationale is that the engine stop fires "only at the first intervention
of the first region", so the condition must be asserted "before any region work starts". A
min/max range test only proves the *envelope*: any interior value in `[0, 1]` is invisible to it.
A fuzzy/probability-style mask, or a `{0,1}` mask with stray resampled fringe values, passes Stage
7 and then hard-stops hours later inside the first region. Verified:

```
frac minmax: 0 1
frac runtime: intervention mask .../frac.tif has value(s) outside {0,1,NA}: 0.5
```

**Fix:** one streaming scan of the same cost class as `minmax()` tests the real predicate and
subsumes WR-01:

```r
              fq <- suppressWarnings(tryCatch(terra::freq(m), error = function(e) NULL))
              if (is.null(fq)) {
                intervention_errors <- c(intervention_errors, sprintf(
                  "intervention mask: %s values could not be read", mask_path))
                next
              }
              vals <- fq$value[!is.na(fq$value)]
              bad <- setdiff(vals, c(0, 1))
              if (length(bad) > 0L) { ... "has value(s) outside {0,1,NA} (observed %s)" ... ; next }
              if (!any(vals == 1)) { ... "has no cell equal to 1" ... ; next }
```

Keep the existing all-NA tolerance (`length(vals) == 0L` → the domain claim is vacuously true),
so the behaviour the wiring test pins at
`tests/testthat/test-spatial-interventions-wiring.R:556-573` is unchanged.

### WR-03: The new pre-flight `tryCatch` fallbacks convert an unreadable mask into a PASS of the value gate

**File:** `src/allocation.r:653-655` (`is_cat`) and `src/allocation.r:680-683` (`mm`)

**Issue:** both guards swallow every error into a value that means "nothing to report":
`is.factor` failure → `FALSE`, `minmax` failure → `c(NaN, NaN)` → `all(is.finite(mm))` is `FALSE`
→ no error recorded. A mask whose *header* reads but whose value blocks do not (truncated upload,
beegfs read error, corrupt compression — the staging failures this gate exists for) therefore
passes the value-domain gate silently and is only discovered mid-run. The `length(mm) == 2L`
term has the same property: any unexpected shape degrades to "accept". This is the same
error-swallowing pattern the phase's own D-02 comment warns against for the finiteness term.

**Fix:** distinguish "all NA" (tolerated, by design) from "could not read":

```r
              mm <- suppressWarnings(tryCatch(
                as.vector(terra::minmax(m, compute = TRUE)),
                error = function(e) conditionMessage(e)
              ))
              if (is.character(mm) || length(mm) != 2L) {
                intervention_errors <- c(intervention_errors, sprintf(
                  "intervention mask: %s values could not be read (%s)",
                  mask_path, if (is.character(mm)) mm else "unexpected minmax shape"))
                next
              }
```

### WR-04: The WR-04 downgrade also swallows a genuinely empty probability map

**File:** `scripts/verify_intervention_smoke.r:395-403`

**Issue:** the downgrade is right for its stated cause (a per-transition map whose from-class does
not intersect the mask), but `n_zone == 0` has a second cause the new branch cannot distinguish:
a probability map that is **entirely** NA over the region, i.e. an engine/write defect. Before this
phase that was a FAIL; now it is `Info: ... not counted`, and when at least one sibling map asserts
successfully the run still reports PASS (D-06a only fires when *all* of an intervention's maps are
skipped). The two causes are cheaply separable, because `r` having no non-NA cell anywhere in the
region is never an ordinary outcome for a written probability map.

**Fix:**

```r
          n_zone <- terra::global(sel & !is.na(r), "sum", na.rm = TRUE)[[1]][1]
          if (!is.finite(n_zone) || n_zone == 0) {
            n_r <- terra::global(!is.na(r), "sum", na.rm = TRUE)[[1]][1]
            if (!is.finite(n_r) || n_r == 0) {
              # not the WR-04 shape: the map itself carries no probability at all
              fail(sprintf("%s: %s has no non-NA probability cell anywhere in this region",
                           id, basename(tif)))
            } else {
              cat(sprintf("  Info: %s %s has no non-NA cells in zone=%s ...; not counted\n",
                          id, basename(tif), zone))
            }
            next
          }
```

## Info

### IN-01: One pre-flight mask rejection is reported twice by the verifier's forbidden scan

**File:** `scripts/verify_intervention_smoke.r:620-628`
**Issue:** the Stage 7 wording `"intervention mask: <path> has value(s) outside {0,1,NA} (...)"`
matches both the pre-existing `"intervention mask: "` marker and the new `"outside {0,1,NA}"`
marker, so a single bad mask produces two `fail()` entries and inflates the
`errors=N` count in the FAIL banner. Same for `"is categorical/non-numeric"`.
**Fix:** `break` out of the `for (f in forbidden)` loop after the first hit on a given line, or
de-duplicate hits per line before calling `fail()`.

### IN-02: The engine and the pre-flight detect "categorical" by two different mechanisms

**File:** `src/implement_spatial_interventions.R:338-343` vs `src/allocation.r:653-665`
**Issue:** the pre-flight asks `terra::is.factor(m)` directly; the engine infers it from
`terra::extract()` happening to return a `factor`. I verified the two agree on terra 1.9.34, but
the engine's half depends on an undocumented return-type behaviour of `extract()`. If a future
terra returns integer *codes* instead, `is.numeric(v)` becomes `TRUE` and the engine silently
compares level codes (1-based) against `{0,1}` rather than raster values.
**Fix:** make the engine assert the same proposition explicitly, keeping `is.numeric()` as a belt:
`if (isTRUE(terra::is.factor(m)) || !is.numeric(v)) stop(...)` — the message literal stays frozen.

### IN-03: The reported bad-value list is silently truncated

**File:** `src/implement_spatial_interventions.R:344-350`
**Issue:** `utils::head(bad, 5L)` drops the rest with no indication, so an operator reading
`...: 2, 3, 4, 5, 6` cannot tell whether the mask has 5 bad values or 5000. `5L` is also a bare
magic number.
**Fix:** append the count, e.g. `sprintf("%s (%d distinct bad value(s))", paste(utils::head(bad, 5L), collapse = ", "), length(bad))`.

### IN-04: The value-domain block `next`s before the grid check, hiding a second defect on the same mask

**File:** `src/allocation.r:644-694` relative to `:695-706`
**Issue:** a mask that is both 255-coded and mis-gridded now reports only the value-domain error;
the operator fixes the burn value, re-runs Stage 7, and only then learns the grid is wrong. The
pre-flight's purpose is to surface everything before the multi-hour run. This matches the
pre-existing `nlyr` branch's one-error-at-a-time style, hence Info rather than Warning.
**Fix:** accumulate into a per-mask error vector and run all four checks (nlyr, categorical,
value domain, geometry) before moving to the next mask, instead of `next`ing on the first.

### IN-05: Nothing ties the engine's frozen wording to the verifier's `forbidden` vector

**File:** `tests/testthat/test-verify-intervention-smoke.R:384-390` and
`tests/testthat/test-spatial-interventions.R:419-444`
**Issue:** the contract is asserted twice, independently: one test greps the *verifier source*
for the literals, another expects the *engine message* to match them. Neither reads the other, so
the pair only works because a human kept the two literals in sync; a coordinated paraphrase of
both (or of the engine message plus the verifier list in the same commit) satisfies both tests
while breaking nothing visibly. `grepl("outside {0,1,NA}", src, fixed = TRUE)` also passes on a
mere *comment* occurrence in the verifier, not only on the `forbidden` vector entry.
**Fix:** one test that parses the verifier's `forbidden` vector (source the script's vector, or
`eval(parse(...))` of the `forbidden <- c(...)` block) and asserts that the real
`.mask_inside_lut()` stop message for a 255 mask and for a categorical mask each match at least
one element of it with `fixed = TRUE`. That makes the contract self-enforcing in a single place.
