<objective>
Close R51-IN-05 (`05.1-REVIEW.md`, restated in `05.1-VERIFICATION.md`): make D-03's cross-file wording
contract self-enforcing.

The hole is a test-validity hole in a guard this phase shipped. The contract between the engine, the
Stage 7 pre-flight and the smoke verifier is asserted twice, independently:
`tests/testthat/test-verify-intervention-smoke.R:384-390` greps the verifier SOURCE TEXT for the literals
(`grepl("outside {0,1,NA}", src, fixed = TRUE)`), and `tests/testthat/test-spatial-interventions.R:419-444`
expects the engine message to match them. Neither reads the other, and the first passes on a mere COMMENT
occurrence — the verifier's own rationale comment quotes both substrings, so deleting the `forbidden`
entries would leave the test green while the verifier stops treating those stops as fatal. D-03's gate
therefore does not prove what it claims.

Fix: one test that (1) parses the `forbidden <- c(...)` literal out of the verifier with
`eval(parse(text = ...))` (plan 05.1-04 guarantees the block is a self-contained literal expression for
exactly this reason), and (2) asserts every frozen substring appears in a STRING LITERAL — not a comment —
of each file contractually required to emit it. "String literal, not comment" is enforced with the R parser
(`utils::getParseData()` `STR_CONST` tokens), not with a `^\\s*#` line filter, because a line filter is
fooled by a trailing comment (`x <- 1 # has no cell equal to 1`) and by a substring split over two literals.

A test of a guard is only worth having if it can fail. Task 2 therefore proves this one non-vacuous with
synthetic sources AND with mutated copies of the two real files in which the contract text is kept only in
a comment.

Purpose: a coordinated paraphrase — or a deleted `forbidden` entry — breaks a test instead of passing
silently, which is the only property that makes a frozen cross-file contract frozen.
Output: a parse-based helper, one contract test file, and the weak source-grep block retired.
</objective>
