## Accomplishments

- Inserted the stage 2->3 audit block immediately after `reconcile_period_transitions()` in `perform_transition_modelling()`. Emits `AUDIT stage=2->3 period=P expected=N fs_success=M fs_failed=K fs_missing=J` via `message()`, and emits a `warning()` listing each affected `transition@region[status]` pair when `(K + J) > 0`. Counts derive directly from the `fs_status` column of the reconciliation tibble.
- Added per-region precompute of `n_viable_input` and `n_forbidden_excluded` at function scope inside `optimize_region_scenario()`, sourced from the already-in-scope `df_trans_source` and `forbid_pairs_df` parameters. These values are loop-invariant for the region and re-used across every timestep.
- Inserted the stage 4 audit log line after every `readr::write_csv()` of a per-timestep rate CSV: `AUDIT stage=4 scenario=S region=R timestep=Y viable_input=N forbidden_excluded=K rate_csv_rows=M`. This lets an operator verify that the row count written to disk matches the viable input minus forbidden exclusions (or surface the gap if it does not).
- Replaced the silent `warning(log_msg(...))` on missing models in `generate_probability_maps()` with a `stop(log_msg(...))` that names the missing `id_trans` value(s) and instructs the operator to re-run `transition_modelling()` or trim `viable_transitions_lists.csv`. Added a structured `AUDIT stage=5 region=L rate_table_rows=R model_count=M missing_model_id_trans=ids|none` line BEFORE the stop so the audit line is captured for both the pass and fail paths.

## Decisions Made

- **Comment header re-phrased to "Stage 2 -> 3 boundary audit" rather than "AUDIT stage=2->3"** so that the literal grep `grep -n "AUDIT stage=2->3" src/transition_modelling.r` returns exactly one line (the `sprintf` format string at line 902). This matches the Plan 01 convention where the stage 1->2 emission is a single line, and prevents accidental double-emission if a future reader copies the comment marker into a real `message()` call.
- **Stage 4 precompute placed at function scope, not inside a region for-loop.** `optimize_region_scenario()` is the per-(r, s) worker — there is no enclosing region for-loop in this function. The plan's wording "inside the region for-loop" referred to the conceptual region iteration that happens one call up in `run_scalar_optimization_loop()`. Since `df_trans_source` and `forbid_pairs_df` are already function parameters of `optimize_region_scenario()` (signature lines 564, 569), the precompute can sit at function scope directly above the inner timestep loop without any plumbing changes.
- **Stage 5 audit uses `log_msg()` (file-routed) while stages 2->3 and 4 use `message()`.** Each emission point matches the local file's existing convention: `generate_probability_maps()` already routes all operator-facing output through `log_msg(..., log_file)` (see surrounding stop/warning blocks at lines 1914, 1928, 1979); `perform_transition_modelling()` and `optimize_region_scenario()` emit via `message()` to stderr without a `log_file` parameter in scope. Forcing one channel would have required either passing `log_file` into `perform_transition_modelling()` or stripping log_file from the surrounding `generate_probability_maps()` block — both are larger changes than this plan authorizes.
