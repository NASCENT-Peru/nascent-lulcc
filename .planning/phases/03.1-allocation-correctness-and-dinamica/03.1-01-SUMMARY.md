# Phase 3.1 Summary — Allocation Correctness & Dinamica Integration

## Outcome

Phase goal achieved. First end-to-end allocation run including the Dinamica CA step completed
successfully on Euler HPC (2026-05-25) with **4,477 cells changed in `posterior.tif`** —
confirming Dinamica actually executed real spatial allocation, not just a metadata-different
copy of the anterior map.

Root cause of the initial 0-cell result was traced to a corrupted demand input CSV — the
`confidence_factor` column had Excel-introduced thousand-separator commas that broke the
`clean_numeric()` parser, silently zeroing out all expert demand input and starving the
transition rate optimizer of meaningful targets.

---

## Fixes Applied

### Fix 1 — Dinamica HPC fallback guard (src/dinamica_utils.r ~643)
**Root cause:** `run_allocation_dinamica()` short-circuited on `Sys.which("DinamicaConsole") == ""`
before reaching the apptainer path. On HPC, only apptainer is available.
**Fix:** Fallback guard only fires when `detect_dinamica_backend() == "local"`. On HPC,
`exec_dinamica()` is called normally via apptainer.

### Fix 2 — Phantom NA TIFs (src/allocation.r ~2273)
**Root cause:** `normalized[.(k)]` with default `nomatch = NA` produced rows with NA
probability for transitions without predictions, writing 1-cell NA placeholder TIFs.
**Fix:** Changed to `normalized[.(k), nomatch = NULL]` — unmatched keys return empty table.

### Fix 3 — Model over-loading (src/allocation.r ~545–716)
**Root cause:** `load_allocation_models` loaded all .qs files on disk regardless of which
transitions were active in the current scenario × year.
**Fix:** `load_allocation_models` accepts `active_transitions`; `prepare_region_worker_inputs`
reads trans_rates CSV and filters before deserializing.

### Fix 4 — Apptainer bind-mount in R (src/dinamica_utils.r ~272)
**Root cause:** `resolve_dinamica_launch()` bound only `staged_tmp` into the container; the
allocation `.ego` and probability maps live under `hpc_scratch_root` which was unbound.
**Fix:** `--bind` now uses `paste0(hpc_scratch_root, ":", hpc_scratch_root)`.

### Fix 4b — Apptainer bind-mount in shell (scripts/smoke_test_dinamica.sh ~318)
**Root cause:** LAUNCH_CMD diverged from R per D-104 mirror contract.
**Fix:** Changed to `--bind "${HPC_SCRATCH_ROOT:-$STAGED_TMP}:${HPC_SCRATCH_ROOT:-$STAGED_TMP}"`.

### Fix 5 — Demand CSV thousand-separator corruption (scripts/reexport_demand_csv.py — new)
**Root cause:** The source `LULC_demand_results.xlsx` stored `Confidence factor` and
`Initial rate` as European-format strings (single comma decimal, e.g., `"1,772004996"`). A
prior Excel save-as-CSV step interpreted these as integers and inserted thousand separators
every 3 digits, producing `"1,772,004,996"`. The R `clean_numeric()` function in
`src/simulation_trans_rates_prep.r` only handled single-comma format — multi-comma values
became `NA` after `gsub(",", ".")`. NaN means → 0 via `if_else(is.na, 0, ...)` → 
`slider_adjustment = 0` → `final_frac ≈ init_frac` → optimizer's `diffs == 0` constraint pinned
area constant across all timesteps → transition rates collapsed to ~1e-11 numerical noise.

**Fix:** Re-export `lulc_demand_results.csv` directly from the XLSX with proper dot-decimal
formatting via `scripts/reexport_demand_csv.py`. Existing `clean_numeric()` now parses cleanly.
The broken file is preserved as `lulc_demand_results_broken.csv.bak`.

## Follow-up Concern (Non-blocking)

Dinamica's "Remaining Transitions" matrix shows tens of thousands of unallocated cells per
from→to pair, but only 4,477 actual reclassifications occurred. The change matrix demanded
much more change than Dinamica could place. Candidates:
- Probability map saturation (too few high-probability eligible cells)
- Patcher patch parameters too restrictive
- `Perc_expander` values too high (90%+) starve the Patcher

This is a model behavior / calibration concern beyond Phase 3.1's scope and does not block
phase completion.
