<objective>
Gate, launch, and verify the live single-scenario run. Three operator-gated steps:

1. **D-11 rate-table pre-flight (HARD BLOCKING PREREQUISITE).** A script confirms that for the
   chosen schedule (`simulation_year_steps`, head -1 = the `year_ant` set 2022,2024,…,2056) a
   `BAU-<region>-trans_rates-<year_ant>.csv` exists for EVERY `year_ant` x EVERY region on HPC
   scratch, plus the demand table `tools/simulation_lulc_areas_2060.csv`. The allocation loop reads
   one rate CSV per `year_ant` (`src/allocation.r:786-792`); a missing one makes that timestep
   stop(). If tables exist only for 2022 (the single-timestep state so far), every later `year_ant`
   needs its CSV first — a Stage-4 re-run prerequisite (echoes Phase 3.4 / PIPE-08). The gate BLOCKS
   the run and prints the exact missing (region, year_ant) list. Also enforce PIPE-09: `git pull` +
   clean `git status` so the HPC tree is at the intended head before any submission.

2. **Live HPC run.** Submit `scripts/submit_allocation_scenario.sh` (per-region fan-out + afterok
   mosaic). Monitor; on a dead region job, resubmit (the launcher's D-09 resume skips completed
   timesteps). This is a multi-hour, multi-region run on highmem nodes — an OPERATOR task.

3. **Verification.** Run `scripts/verify_allocation_run.sh BAU`; require PASS (full matrix exists,
   every posterior differs from its anterior, national mosaics for every timestep). A persistently
   failing region is a blocker tracked to resolution or escalated to Phase 4 — not silently dropped.

Purpose: This is the capstone proof — the full Phase 3 machinery driven to completion at scale,
declared done by the manifest, not by log eyeballing.
Output: `scripts/preflight_rate_tables.sh` (the blocking gate) + the live posterior series + national
mosaics + `run_manifest.csv` (PASS) on HPC.
</objective>
