## Root Cause

`DFF::LogManager::Instance()` in `libBase.so` uses a C++ local static guard
(`__gnu_cxx::__cxa_guard_acquire`) for singleton initialization. During its first call
(from `StaticUtils::initialize()` at `DinamicaConsole` startup), the initialization chain
calls back into `LogManager::Instance()` before initialization completes:

```
LogManager::Instance()  [guard locked — init begins]
  → LogHub::LogHub()
    → ApplicationUtils::getLogPath()
      → FilesystemHelperManager::Instance()
        → FilesystemHelper::FilesystemHelper()
          → getNewTemporaryDirectory()
            → getContextualLog()              ← re-enters LogManager::Instance()
              → LogManager::Instance()        [guard already locked → THROWS]
```

This is a code bug in Dinamica EGO 8's `libBase.so`. It is independent of:
- Ubuntu version (identical crash on Noble 24.04 and Jammy 22.04 — H5 FALSIFIED)
- Missing libraries (LD_DEBUG=libs shows zero errors — H3 FALSIFIED)
- Environment variables (exhaustive sweep of all DINAMICA_EGO_8_* vars — H2 FALSIFIED)
- Configuration keys (GdalToolsData and all other conf keys tried — H4 FALSIFIED)

## Fix (Handed to Plan 07)

LD_PRELOAD interceptor (`dinamica/container/dinamica_init_fix.cpp`) intercepts two symbols:

1. `_ZN3DFF10LogManager8InstanceEv` — sets TLS flag `logmanager_in_init=1` before calling real;
   returns `nullptr` if called re-entrantly (flag already 1).
2. `_ZN3DFF16getContextualLogEv` — returns `nullptr` immediately if `logmanager_in_init=1`.

At the call site: `canLogMessage(nullptr, tag, subsystem)` returns `false` → logging call skipped
safely → `getNewTemporaryDirectory()` completes → entire init chain completes → version banner
printed.

Plan 07 bakes this into `%post` (Stage 6 compile) and `%environment` (`LD_PRELOAD` export).
