- too weak (GAP-3): an all-`0.5` mask has `minmax` = `0.5 0.5`, passes, and

- too weak (GAP-2): an all-zero mask has `minmax` = `0 0`, passes, and the engine's
  `bad <- v[!is.na(v) & v != 0 & v != 1]` is empty for it too, so with `Prob_adjust_zone: Outside`
  the all-FALSE LUT makes the zone the whole region — the exact impact the phase exists to
  prevent, silently;
- and the two `tryCatch` fallbacks (`:653-655`, `:680-683`) degrade ANY error to "nothing to
  report" (WR-03), so a truncated upload passes the value gate.

Fix (VERIFICATION.md GAP-3 names it): replace the min/max envelope test with ONE
`terra::freq()` scan per unique mask. It tests the real `{0,1,NA}` predicate, additionally tests
"at least one cell equals 1", and subsumes GAP-2. Prefer this single scan to bolting
`mm[2] != 1` onto the range test.

TWO TRAPS this plan must not fall into, each pinned by a fixture:

1. `terra::freq()` ROUNDS to `digits = 0` by default (verified on terra 1.9.34: an all-`0.5`
   raster reports `value = 1`). A bare `freq(m)` would therefore read the all-0.5 mask as a valid
   all-1 mask and GAP-3 would stay open while looking fixed. `digits = 12` is mandatory.
2. `any(vals == 1)` is `FALSE` for an EMPTY `vals`, so an all-NA mask would be rejected as "no
   cell equal to 1". All-NA is tolerated by design (its degeneracy is the verifier's D-04 job), so
   the empty-`vals` branch MUST be tested BEFORE the no-1 test.

Purpose: Stage 7 rejects every mask the engine would later reject — or that would silently invert
a zone — before any region work, and never mistakes "could not read" for "nothing to report".
Output: a rewritten value block in the pre-flight loop, six new pre-flight fixtures, two
corrected operator documents.
