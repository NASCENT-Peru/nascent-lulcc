<objective>
Add cross-stage boundary audit hooks that log structured messages whenever viable transition counts change between pipeline stages. Three insertion points:

1. **Stage 2→3 (transition_modelling.r):** After `reconcile_period_transitions()` in `perform_transition_modelling()`, log a structured summary of FS success/failed/missing counts. Emit a `warning()` listing the affected transitions when any failures or missing entries exist.

2. **Stage 4 (simulation_trans_rates_prep.r):** Inside `optimize_region_scenario()`, after building `rate_df` and filtering out persistence rows (`!is.na(id_trans)`), log viable input count, forbidden-excluded count, and rate CSV row count for each scenario × region × timestep.

3. **Stage 5 (allocation.r):** In `generate_probability_maps()`, promote the existing `warning()` for `missing_models` to a `stop()` so model-count mismatches are hard failures, not silent warnings. Add an AUDIT log line before the stop.

Purpose: These hooks close the "no count verification between stages" gap identified in Phase 3.2 research. They do NOT change pipeline logic — only add observability.

Output: Modified `src/transition_modelling.r`, `src/simulation_trans_rates_prep.r`, `src/allocation.r`.
</objective>
