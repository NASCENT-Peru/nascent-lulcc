### Logging — `log_msg()` from `src/utils.r:1016-1024`

**Source:** `src/utils.r:1016-1024`
**Apply to:** every R-side change in this phase (allocation.r insertions, saturation_diagnostics.r helpers, standalone script).

```r
# Source: src/utils.r:1016-1024
log_msg <- function(msg, log_file = NULL, also_console = TRUE) {
  timestamp <- format(Sys.time(), "%Y-%m-%d %H:%M:%S")
  line <- paste0(timestamp, " | ", msg, "\n")
  if (!is.null(log_file)) {
    dir.create(dirname(log_file), recursive = TRUE, showWarnings = FALSE)
    cat(line, file = log_file, append = TRUE)
  }
  if (also_console) cat(line)
}
```
**Usage convention:** always pass `log_file` (the per-worker log path) when inside a parallel worker so messages land in both the per-region log AND stdout (SLURM `.out` capture). For the standalone script, pass `log_file = NULL` (default) — messages go to stdout only.

**Never** use `message()` or `cat()` directly for AUDIT/SATURATION/PROFILE lines — those must go through `log_msg()` so they land in the per-worker log file consistently.

### AUDIT log line grammar — Phase 3.2 convention

**Source:** `.planning/phases/03.2-transition-pipeline-consistency/03.2-01-PLAN.md:203` and `03.2-02-PLAN.md:26-45`
**Apply to:** the new `AUDIT stage=saturation ...` line and the new `AUDIT stage=allocation_filter ...` line.

Grammar: `AUDIT stage=<stage_name> [scenario=<S>] [region=<R>] [key=value ...]`
- `stage=` value uses lowercase + underscores or `->` for cross-stage transitions (`stage=1->2`, `stage=saturation`, `stage=allocation_filter`).
- `key=value` pairs use `=` separator (no spaces), space-separated.
- Numeric values formatted with `%d` for integers, `%.2f` for thresholds/fractions.
- Final formatting goes through `sprintf(...)` wrapped in `log_msg(...)`.

### `terra::values(mat = FALSE)` + base-R vector ops — `src/calibrate_allocation_parameters.r:1005-1014`

**Source:** `src/calibrate_allocation_parameters.r:1005-1014`
**Apply to:** all `saturation_diagnostics.r` metric computations.

```r
# Pattern: pull raster to vector once, do all aggregations in base R
anterior_vals <- terra::values(anterior, mat = FALSE)
posterior_vals <- terra::values(posterior, mat = FALSE)
# Pair count: avoid building intermediate logical rasters
placed_cells <- sum(anterior_vals == from_val & posterior_vals == to_val, na.rm = TRUE)
# Class-cell count for area_t denominator
area_t <- sum(anterior_vals == from_val, na.rm = TRUE)
```
**Why this idiom and not `terra::global()`:** for many transitions (~30), iterating raster ops via `terra::global()` re-walks the raster N times. Vectorising into base R once and aggregating in a loop is O(N×cells) rather than O(N×raster-ops). The existing `calibrate_allocation_parameters.r` pattern already uses this approach for the same reason (one-shot pair counting).
