# Phase 03.5 Plan 02: Lazy Per-From-Class Predictor Read Summary

Replaced the eager full-region predictor preload with a lazy, cached, per-from-class Arrow read (`load_from_class_predictor_data()`) gated behind `ALLOCATION_PREDICTOR_LAZY` (default ON), so per-region predictor RAM is bounded by the largest single from-class table instead of the full region table — while preserving the downstream `J(lookup_keys), nomatch = NA` keyed left-join byte-for-byte so per-transition coverage is unchanged.

## What Was Built

- **`load_from_class_predictor_data()`** (`src/allocation.r`, immediately after `preload_region_predictor_data()`): the per-from-class analogue of the eager preload. Signature `(ds_static, ds_dynamic, cols, region_value, scenario, ref_cell_keys, log_file = NULL)`. It builds `key_tbl <- arrow::arrow_table(cell_id = ref_cell_keys)` and reads static columns (`filter(region == region_value)`) and dynamic columns (`filter(region == region_value, scenario == scenario)`) via `dplyr::select(cell_id, all_of(cols)) |> dplyr::inner_join(key_tbl, by = "cell_id") |> collect()` (RESEARCH Pattern 1) — **never** `cell_id %in% big_vector` (Pitfall 1). Sources are merged by `cell_id` with `all = TRUE` (identical to the eager merge) and keyed by `cell_id`. Empty `cols` or empty `ref_cell_keys` return an empty `cell_id`-only `data.table`. A `log_msg` records key count, resulting `nrow`, and the static/dynamic columns, mirroring the eager preload log.
- **`get_allocation_predictor_lazy()`** (`src/allocation.r`, after `get_allocation_predict_num_threads()`): a boolean resolver mirroring `get_allocation_predict_batch_rows()`. Reads `ALLOCATION_PREDICTOR_LAZY`; `"0"/"false"/"no"/"off"` (case-insensitive, trimmed) => `FALSE`; everything else (including unset/empty/`"1"`/`"true"`/`"yes"`) => `TRUE` (default ON).
- **Per-from-class cache + eager gate** in `generate_probability_maps()`: a loop-entry `log_msg` records which path (lazy vs eager) is active and the resolved knob value. When lazy is `FALSE`, the original `preload_region_predictor_data()` call runs unchanged (escape hatch). When lazy is `TRUE`, the eager preload is skipped; instead `col_union_by_from` (the per-`from_val` column union, minus `_nhood_`) is precomputed and a `from_class_cache <- new.env(parent = emptyenv())` is created. Inside the per-transition loop, after `from_idx` is computed, the cache is populated once per distinct `from_val` (`as.character(from_val)` key) via `load_from_class_predictor_data(..., ref_cell_keys = from_idx$ref_cell_id)`, profiled under `stage=predictor_load`; `region_pred_dt` is then set to the cached from-class-sized table. The L2557-2565 keyed left-join (`region_pred_dt[J(lookup_keys), nomatch = NA]`) is **unchanged** and now operates against the from-class-sized table (Pitfall 4). The batch loop (`ALLOCATION_PREDICT_BATCH_ROWS`) is untouched (Pitfall 6 — composes downstream of the read).
- **Smoke-script knob surface** (`scripts/submit_allocation_smoke.sh`): `export ALLOCATION_PREDICTOR_LAZY=${ALLOCATION_PREDICTOR_LAZY:-}` (empty default keeps lazy ON) plus an echo line `ALLOCATION_PREDICTOR_LAZY=${...:-<unset: lazy per-from-class ON>}`, mirroring the Wave 1 thread-knob echo.
- **Test + fixture** (`tests/testthat/test-allocation-lazy-predictor.R` + `tests/testthat/fixtures/lazy_predictor/README.md`): a synthetic hive-partitioned parquet fixture built reproducibly at test time (region=int32 static; scenario=utf8 + region=int32 dynamic), mirroring `src/allocation.r` L2237-2249. Assertions: (0) the function exists; (1) lazy == eager preload restricted to the same keys/cols (cell_id setequal + per-column equality); (2) only requested keys/cols/region returned (projection + scoping); (3) a per-from-class cache collects once per distinct `from_val` (scan-count counter, RESEARCH Pattern 2); (4) empty cols/keys => empty `cell_id`-only table. The fixture deliberately omits region-1 dynamic rows for cell_ids 151..200 so the NA-fill keyed join is exercised.

## Threat Model

- **T-03.5-02 (Information disclosure / correctness — lazy inner_join dropping cells the eager left-join kept):** mitigated. The lazy read scopes the predictor table to a from-class's keys, but the downstream `region_pred_dt[J(lookup_keys), nomatch = NA]` keyed LEFT join is preserved verbatim, so a from-class cell missing from the predictor parquet is KEPT with NA (never dropped). The fixture's omitted region-1 dynamic rows (151..200) exercise exactly this NA-fill path. Plan 03 asserts per-transition cell counts identical to baseline on real data.
- **T-03.5-03 (DoS / perf regression — per-transition re-scan reintroducing %in% slowness):** mitigated. Selection uses `inner_join(arrow_table(keys))` (Acero hash-join pushdown), and the per-from-class cache reads each distinct from-class at most once. `ALLOCATION_PREDICTOR_LAZY=0` is the bisect escape hatch to the eager path.
- **T-03.5-NA (external network/web):** accept — internal HPC compute change only; no external surface. No package installs (no supply-chain gate required).

No new security-relevant surface introduced beyond the read-only operator env knob added to the threat register.
