### CR-01 engine guard (D-01) — VERIFIED

`src/implement_spatial_interventions.R` ~L337-352, immediately after `terra::extract()`:

1. `!is.numeric(v)` is checked **first** — correct, because `!=` is meaningless on a
   factor. Message: `is categorical/non-numeric; expected numeric {0,1,NA}`.
2. Then `v[!is.na(v) & v != 0 & v != 1]` → `has value(s) outside {0,1,NA}: ...`.
3. The LUT is built only after both checks pass.

Fixtures in `test-spatial-interventions.R` cover a 255-valued mask, a categorical mask
and a 1-coded control. 63 tests, 0 failures.

### CR-01 pre-flight (D-02) — VERIFIED

`src/allocation.r` ~L650-700. Order: `nlyr` → `terra::is.factor` → `terra::minmax(compute
= TRUE)` range check → `compareGeom`. The range check is guarded by `all(is.finite(mm))`,
so an all-NA mask does not crash it with "missing value where TRUE/FALSE needed" (itself
a forbidden marker). A wiring test pins this. Out-of-domain, categorical, valid-silent and
all-NA fixtures: 43 tests, 0 failures.

**Design note, not a gap — the two halves are not equally strict.** The pre-flight only
rejects values outside the *range* `[0,1]`, because `minmax` is all it looks at. A
fractional mask (every cell `0.5`, say) has `min == max == 0.5` and therefore **passes**
the pre-flight, then stops at the D-01 runtime guard once a region is reached. So the
"fail before any region work starts" property holds for the 255-style and categorical
cases this phase was built for, but not for fractional values. That is inherent to the
cheap `minmax` design the plan chose for D-02 and is not a defect against any must-have;
it is recorded here so nobody later mistakes the pre-flight for a complete mirror of the
runtime guard.

### GAP-1 — BLOCKER. The verifier can print PASS with an entire Absolute-0 intervention unasserted

`scripts/verify_intervention_smoke.r`:

- `:333-336` — `length(rows) == 0L` prints one `Info:` line and `next`s. It sits **above**
  `degeneracy_checked <- FALSE` (`:346`), the D-04 degeneracy proof (`:373-384`) and D-06a
  (`:431-436`). So an intervention with no target rows gets **no degeneracy check and no map
  check**.
- `:445-450` — D-06b is a **run-level** floor on `maps_checked`. A sibling intervention that does
  have rows keeps `maps_checked > 0`, so D-06b never fires and the script exits 0.
- `:429-430` — the comment claiming the no-rows case "is caught run-level by D-06b" is **false**
  whenever two or more active Absolute-0 interventions exist.
- `:25-27` — the header contract ("per intervention: zero checked maps is a FAIL") is therefore
  **stronger than the code**.

**This is the shipped config shape,** verified in `config/NAT_interventions.yml`:
`Conservation_expansion_and_preservation` is `Absolute`/`0`/`Inside` with three target classes (so
it almost always has rows), while `Mining_freeze_post_2030` is `Absolute`/`0`/`Outside` with
`Transition_target_classes: mining` alone. Any region/year with no `* -> mining` transition row
silently skips the Outside intervention's D-04 while the sibling keeps the banner green — and that
green banner is then read as evidence for both.

**Effect on the phase goal:** CR-01's observational blind spot persists for exactly those
region/years. The two production runs already banked are *not* affected — `Mining_freeze_post_2030`
had 4 checked maps in both costa_peruana and andes at 2032, so D-04 ran and passed there. The gap
is about other region/years and about every future run.

**Why the fixtures missed it:** there is no multi-intervention Absolute-0 fixture. `:348-357`
(D-06b) and `:359-369` (D-04) both pin the single-intervention shape.

Suggested fix: hoist the D-04 degeneracy proof above the rows check (it needs only `m_nat` and
`zone`), and add an `unasserted_ids` ledger that fails at run level for any active Absolute-0
intervention never asserted on.

### GAP-2 — WARNING. An all-zero mask passes BOTH new guards

- Engine (`implement_spatial_interventions.R:347` context): the bad set is
  `v[!is.na(v) & v != 0 & v != 1]`, which is **empty** for an all-zero mask — no stop.
- Pre-flight (`allocation.r:684-685`): the condition is `!(mm[1] >= 0 && mm[2] <= 1)`, and `minmax`
  returns `(0, 0)`, so `!(TRUE)` is FALSE — no error.

With `Prob_adjust_zone: Outside` the resulting all-FALSE LUT makes the zone the whole region —
**the exact CR-01 impact this phase exists to prevent**, silently. The all-NA case is a documented,
deliberate delegation to D-04; the all-zero case is undocumented, and per GAP-1 D-04 can be skipped
entirely. Cheap fix: `mm` is already in hand, so also reject `mm[2] != 1`.

### GAP-3 — WARNING. The pre-flight is range-only (the design note above, restated as a gap)

`!(mm[1] >= 0 && mm[2] <= 1)` admits any in-range value, so an all-`0.5` mask passes Stage 7 and
hard-stops hours later in the first region — defeating the block's own stated purpose of rejecting
bad masks "before any region work starts". One `terra::freq()` scan (same cost class as `minmax`)
tests the real predicate and would subsume GAP-2.

### Also reported by the review, not independently re-derived here

- Both new `tryCatch` fallbacks (`allocation.r:653-655`, `:680-683`) degrade **any** error to
  "nothing to report", so a mask whose header reads but whose value blocks do not (truncated
  upload, beegfs read error) passes the value gate silently. "All NA" (tolerated by design) should
  be distinguished from "could not read".
- The `n_zone == 0` INFO downgrade (`:395-403`) also swallows a probability map that is entirely NA
  over the region — an engine/write defect that previously FAILed. Discriminate with
  `global(!is.na(r), "sum")`.
- Five Info-tier items (double-counted `errors=N`; the engine inferring categorical from
