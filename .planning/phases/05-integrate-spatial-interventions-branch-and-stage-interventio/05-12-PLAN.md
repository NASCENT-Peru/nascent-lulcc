<objective>
Implement the engine half of the new probability-change telemetry requirement (D-18, D-19, D-20):
every intervention must report summary statistics of the change it makes to cell probabilities, not
just `rows_target` / `rows_changed`.

Purpose: `rows_changed` says how many rows moved but nothing about how far. Scenario review needs
the magnitude and direction of each intervention's effect, per target class, without re-running the
model.

Output: both helpers return a per-target-class statistics table, and the existing
`AUDIT stage=intervention` line gains eight appended fields. The per-intervention CSV is plan 05-13.
</objective>

<interfaces>
FROZEN prefix of the intervention AUDIT line — these fields and this order must not change, because
`scripts/verify_intervention_smoke.r:193-228` parses them:
  AUDIT stage=intervention region=%s scenario=%s year=%d id=%s rank=%s type=%s zone=%s to_vals=%s
  mask=%s rows_target=%d rows_changed=%d

APPENDED fields (D-18), in exactly this order, after rows_changed:
  delta_mean=%s delta_med=%s delta_sd=%s delta_min=%s delta_max=%s n_inc=%d n_dec=%d sum_abs_delta=%s

Per-target-class statistics contract returned by both helpers as `res$stats`, a base data.frame with
one row per element of `Target_classes` (including classes that were skipped), columns in this
order:
  target_class, n_target, n_changed, mean_before, mean_after, sd_before, sd_after,
  p05_delta, p25_delta, p50_delta, p75_delta, p95_delta, min_delta, max_delta, sum_abs_delta,
  prob_mass_before, prob_mass_after, n_inc, n_dec
`target_class`, `n_target`, `n_changed`, `n_inc`, `n_dec` are integer; the rest numeric. A skipped
class emits `n_target = 0L`, `n_changed = 0L`, `n_inc = 0L`, `n_dec = 0L`, `sum_abs_delta = 0` and
`NA_real_` for every mean/sd/percentile/mass field.

D-19 semantics: statistics are computed over the rows the intervention TARGETED — `Target_area_idx`
for Absolute, `sub_idx` for Relative, the same index sets `rows_target` already counts — on the
delta between the values immediately before and immediately after that single intervention's
adjustment. Interventions are sequential, so a later intervention sees the earlier one's output as
its "before". `AUDIT stage=intervention_summary` remains the whole-call roll-up and is unchanged.
