Ship the standalone post-hoc saturation diagnostic CLI — `scripts/diagnose_allocation_saturation.r`. This is the deeper-report counterpart to the inline `saturation_summary.csv` that Plan 02 wires up: same metric helpers, but the standalone surface also (a) classifies each transition as `aligned_ok` / `saturation_bound` / `exempt`, (b) optionally parses the Dinamica log's Remaining-Transitions matrix to cross-validate the inline placed-fraction calculation against Dinamica's own bookkeeping, and (c) prints a tabular console summary so an operator running a one-shot post-hoc diagnosis sees the verdict without opening the CSV.

  Text block in dinamica log with a header line containing "Remaining Transitions"
  followed by a tabular block with column headers (To classes) and row headers

  i.e. from == to) or "--" (no model / blocked transition).

  Example excerpt:
     From \ To |    101     102     103     104     105     106
           101 |   XXXX   37488   72742   21620  122054      89
           102 |  27199    XXXX   40644   13643   75441      89
           ...

  Parser approach (cf. src/dinamica_utils.r:.check_dinamica_post_run() for the
  log-grep pattern): readLines(log_path, warn = FALSE); locate the line matching
  /^\s*From\s*\\\s*To/ (or "Remaining Transitions" header above it); read subsequent
  lines that begin with whitespace + integer + " |"; split on whitespace; first
  token is from-class, remaining tokens are unallocated counts per to-class in
  header order. "XXXX" -> persistence (skip), "--" -> 0 (no transition possible).
