# Phase 05.1 Plan 01: Mask value-domain guard Summary

**A non-1-coded or categorical intervention mask now aborts at `.mask_inside_lut()` and is rejected by the Stage 7 pre-flight, instead of silently reading as "entirely outside" and inverting every `Prob_adjust_zone: Outside` intervention onto the whole region.**

## Accomplishments

- **D-01 (runtime, fatal).** `.mask_inside_lut()` now runs two guards immediately after
  `v <- terra::extract(m, rcid)[[1L]]` and before the LUT is built: a `!is.numeric(v)` check
  (a categorical GeoTIFF round-trips as a factor) followed by
  `bad <- unique(v[!is.na(v) & v != 0 & v != 1])`, reporting the first five offenders via
  `utils::head(bad, 5L)`. This mirrors the THIRD assertion
  `scripts/validate_intervention_masks.r:260-275` makes offline — plan 05-09 had mirrored only
  two of its three. The function's roxygen block now records the value-domain contract.
- **D-02 / D-02b (pre-flight, non-fatal, consolidated).** The `for (mask_path in existing_masks)`
  loop in `validate_allocation_runtime()` gained a categorical check and a value-range check
  between the existing `nlyr` and `compareGeom` branches. Both append an
  `intervention mask: ` line (already on the smoke verifier's forbidden marker list) and `next`.
  A mis-staged mask now costs seconds at pre-flight instead of surfacing at the first
  intervention of the first region — or not at all.
- **The all-NA trap is closed, not created.** `terra::minmax(m, compute = TRUE)` returns
  `NaN NaN` for an all-NA raster; a bare `mm[1] >= 0 && mm[2] <= 1` on that throws
  "missing value where TRUE/FALSE needed", which the smoke verifier treats as fatal. The
  mandatory `all(is.finite(mm))` term is present and has a dedicated regression block.
- **Seven new `CR-01:` test blocks**, three in the engine file and four in the wiring file.
  Engine suite 262 -> 266 passing, wiring suite 129 -> 142 passing, both 0 fail / 0 error.

## Decisions Made

- **Guard order is load-bearing, not stylistic.** `is.numeric()` must precede the `!= 0 / != 1`
  comparisons: for a categorical GeoTIFF `terra::extract()` returns a factor, on which those
  comparisons are meaningless. The plan specified this and it is now enforced by the
  "rejected before the 0/1 comparison" test block.
- **All-NA masks pass the pre-flight value gate.** Rejecting them would require evaluating a
  `NaN` comparison; their degeneracy belongs to the verifier's D-04 assertion (plan 05.1-02),
  not to a value-domain check whose claim they satisfy vacuously. Recorded in a code comment.
- **The D-13 "header-only" claim was corrected rather than deleted.** The pre-flight now does one
  streaming min/max scan per unique mask, so the old comment was false; the amended comment keeps
  the part of D-13 that still holds (nothing is resampled, reprojected or repaired) and states the
  new cost explicitly (once per run, not per region).
- **Helpers were extended, not duplicated.** `value = 1` defaults keep ~30 existing call sites
  behaviourally identical, which the untouched pre-existing assertions confirm.
