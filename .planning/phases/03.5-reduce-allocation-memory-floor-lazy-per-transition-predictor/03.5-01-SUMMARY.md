# Phase 03.5 Plan 01: Scoped Multi-Threaded Ranger Prediction Summary

Added `get_allocation_predict_num_threads()` and threaded its result through both per-transition predict call sites (mlr3 learner `param_set` + direct ranger fallback), bounded by `threads x effective_workers <= cores` and scoped to the ranger predict call only — leaving every other native thread pool pinned to 1 by the untouched `pin_native_threads_to_one()`.

## What Was Built

- **`get_allocation_predict_num_threads()`** (`src/allocation.r`, immediately after `get_allocation_predict_batch_rows()`): a resolver that reads `ALLOCATION_PREDICT_NUM_THREADS`, `ALLOCATION_PARALLEL_STRATEGY`, `ALLOCATION_NUM_WORKERS`, and `SLURM_CPUS_PER_TASK` (falling back to `parallel::detectCores(logical = TRUE)` then 1). It returns an explicit knob value or auto `floor(cores / effective_workers)`, where `effective_workers = 1` under the `sequential` strategy. The result is hard-clamped to `[1, cores %/% effective_workers]` and is always a single integer `>= 1` (never NA, 0, or `> cores`).
- **`num.threads` threaded through both predict sites** in `predict_saved_transition_prob()`: `nthreads` is resolved once per transition (captured by the `predict_block_prob1` closure so it applies identically across `ALLOCATION_PREDICT_BATCH_ROWS` batches), set on the mlr3 learner via `model_obj$learner$param_set$set_values(num.threads = nthreads)` (wrapped in `try()`) before `predict_newdata()`, and passed as `num.threads = nthreads` to the direct `predict.ranger` fallback (replacing the hardcoded `num.threads = 1L`). A one-shot `predict num.threads=%d` log line per transition proves the relaxation took effect. The glmnet fallback is untouched.
- **Smoke-script knob surface** (`scripts/submit_allocation_smoke.sh`): `export ALLOCATION_PREDICT_NUM_THREADS=${ALLOCATION_PREDICT_NUM_THREADS:-}` (empty default keeps auto-derivation) plus an echo line `ALLOCATION_PREDICT_NUM_THREADS=${...:-<unset: auto cores/workers>}` mirroring the existing batch-rows echo.
- **Unit coverage** (`tests/testthat/test-allocation-predict-threads.R`): six tests / twelve expectations covering explicit pass-through, the sequential-strategy denominator (effective workers = 1 => full cores), non-sequential `floor(cores/workers)`, oversize-value clamp, absent-SLURM `detectCores` fallback, and the always-`>= 1` invariant (garbage knob + workers-oversubscribe-cores).
