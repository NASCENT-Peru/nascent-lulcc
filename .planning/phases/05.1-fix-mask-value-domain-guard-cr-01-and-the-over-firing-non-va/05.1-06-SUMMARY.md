# Phase 05.1 Plan 06: Engine mask guard (no-cell-equal-to-1 stop, is.factor categorical test, non-intersection WARN) Summary

The intervention engine now rejects a mask that carries values but has no cell equal to 1 — decided on the mask's **national** value table, not this region's sample — while still letting an all-NA mask and a validly 1-coded mask that merely misses the region through, the latter with one exact non-fatal WARN naming the consequence.

## What was built

**`src/implement_spatial_interventions.R`**

1. `.mask_inside_lut()` — categorical is now asserted with `isTRUE(terra::is.factor(m)) || !is.numeric(v)` (R51-IN-02), so a terra that returned bare integer level codes can no longer slip level codes past a `{0,1}` comparison. The frozen literal `is categorical/non-numeric` is byte-identical.
2. `.mask_inside_lut()` — the value-domain stop names `max_show <- 5L` instead of a bare `5L`, sorts before truncating, and reports the distinct count plus an explicit truncation notice (R51-IN-03). The frozen prefix `intervention mask %s has value(s) outside {0,1,NA}` is unchanged.
3. `.mask_inside_lut()` — new GAP-2 / R51-WR-01 guard, gated on `!any(v == 1, na.rm = TRUE)` so the happy path pays nothing: one `terra::freq(m, digits = 12)` scan, empty-table (all-NA) branch first, then the no-1 stop, then fall-through. The stop precedes `assign(key, lut, envir = cache)`, so a rejected mask is never cached.
4. `implement_spatial_interventions()` — one non-fatal WARN per intervention whose LUT has no TRUE over this region's cells, emitted right after the `.mask_inside_lut()` call and before any probability work. No state changes, no `next`, no stop.
5. Roxygen updated on both functions.

**`tests/testthat/test-spatial-interventions.R`** — 10 new blocks (8 named `GAP-2`, 1 `R51-IN-02`, 1 `R51-IN-03`) and a documentation-only widening of `.write_mask_on()`'s `value` contract (vector allowed; no code change, every existing call site byte-identical).

## (a) The no-1 stop format string, verbatim (COLON-FREE)

```r
"intervention mask %s has no cell equal to 1 (observed value(s): %s); the Inside zone is empty and the Outside zone would be the whole region"
```

Arguments, in order: `mask_path`, `paste(utils::head(sort(vals), max_show), collapse = ", ")`.

Observed at runtime:

```
intervention mask <path>/zero.tif has no cell equal to 1 (observed value(s): 0); the Inside zone is empty and the Outside zone would be the whole region
```

Frozen prefix-free substring for plan 05.1-04's `forbidden` vector: `has no cell equal to 1`. It appears exactly once on a non-comment line, and that line contains `intervention mask %s has no cell equal to 1` and does **not** contain `intervention mask: ` (colon-space). Plan 05.1-05's Stage 7 pre-flight emits the colon-bearing twin; the discrepancy is deliberate.

Arguments, in order:

Observed at runtime (both zones, from the new engine blocks):

Rendered with any arguments it contains none of `has no cell equal to 1`, `intervention mask: `, `outside {0,1,NA}`, `is categorical/non-numeric` (asserted in the task 2 verify).

## (e) R51-IN-04 exclusion note

**R51-IN-04 is deliberately NOT closed here, and this is not an oversight.** Its named site is the Stage 7 pre-flight (`src/allocation.r:644-706`), which `next`s between independent checks and can therefore accumulate and report several findings per mask; plan 05.1-05 closes it there. The engine's order is geometry -> cell lookup -> value domain, all via `stop()`, and the value-domain check is only meaningful once the geometry check has proven the cell numbers address this grid, so "report both findings" has no engine-side meaning. The operator-facing surface for multi-finding reporting is Stage 7. R51-IN-05 belongs to plan 07.
