<objective>
Close WR-08, WR-09 and IN-06 — the test-coverage gaps the review found.

WR-08: `.rel_entry()` only ever produces `Decrease`/`Increase` with `zone = "Inside"`, so two
combinations that the shipped configs actually use have no coverage at all:
`Prob_adjust_valency: Increase_inside_decrease_outside` (NAT and SOC `Urban_densification`, the only
branch that writes to both zones in one pass) and `Prob_adjust_type: Relative` with
`Prob_adjust_zone: Outside` (CUL `Mining_outside_restraint`, where the intervention and
non-intervention index sets are swapped).
WR-09: `"zeros from Absolute=0 stay zero after a Relative Increase"` passes for the wrong reason —
the `Absolute=0` pass leaves no positive probabilities inside the mask, so the NaN guard skips the
Relative intervention entirely. The test proves "a skipped intervention changes nothing".
IN-06: both test files bootstrap with `sys.frame(1)$ofile %||% "."` at file-source time, before
`src/utils.r` is loaded, so they silently depend on base R's `%||%` (R >= 4.4) — which the engine
under test deliberately avoids — and duplicate the same six-line incantation.

Purpose: a production code path with no test is an untested production code path, and a test that
passes for the wrong reason is worse than no test.

Output: a shared helper, two new valency/zone tests, a rejection test, and a corrected
zero-preservation test.
</objective>
