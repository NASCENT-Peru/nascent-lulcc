<objective>
Replace the eager full-region predictor preload (Goal 1 of Phase 3.5) with lazy, per-from-class Arrow reads so per-region predictor RAM is bounded by the largest single from-class table instead of the full region table — cutting the Amazon's ~80 GB preload floor toward the ~10-20 GB target (honestly: may land 20-30 GB; still a 3-4x win) and satisfying Phase 4 SC#4 / PERF-02's worker-side lazy-read clause.

Purpose: The 571309 baseline preloads the full region predictor table (`preload_region_predictor_data()` at src/allocation.r L2183) into `region_pred_dt` — 30.8M cells × 38 cols for the Andes (+13.7 GB / 59.4 GB peak), ~68M cells for the Amazon (the 80 GB floor). N transitions actually share only ~4-8 distinct from-classes. Reading predictors lazily per distinct from-class, with column projection and an inner_join against the sparse from-class cell keys (NOT the known-slow `cell_id %in% big_vector` path the L2176-2179 comment warns about), bounds memory by from-class size and is cached so the dataset is scanned ~(#from-classes) times, not once per transition.

Output: A new `load_from_class_predictor_data()`, a per-from-class cache in `generate_probability_maps()`, an `ALLOCATION_PREDICTOR_LAZY` knob (default ON, `=0` reverts to the eager path for bisecting the central falsifiable risk A3), a smoke-script echo, and a synthetic-fixture equivalence test.
</objective>
