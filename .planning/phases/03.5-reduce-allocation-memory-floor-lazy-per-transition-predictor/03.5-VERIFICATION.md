### Data-Flow Trace (Level 4)

The critical data path is: `from_idx$ref_cell_id` (sparse from-class keys) → `make_key_tbl()` → `inner_join` against parquet → `load_from_class_predictor_data()` → `from_class_cache` → `region_pred_dt` → `J(lookup_keys), nomatch = NA` keyed left-join → `pred_data` → probability prediction.

| Artifact | Data Variable | Source | Produces Real Data | Status |
|----------|---------------|--------|--------------------|--------|
| `load_from_class_predictor_data()` | `static_df`, `dyn_df`, result | `ds_static` / `ds_dynamic` arrow datasets filtered by region/scenario + inner_joined against key table | FLOWING — collect() on real arrow datasets with column projection | VERIFIED |
| `from_class_cache` in `generate_probability_maps()` | `region_pred_dt` | `load_from_class_predictor_data()` return value | Real predictor data from parquet files | VERIFIED |
| `J(lookup_keys), nomatch = NA` keyed join | `pred_data` | `region_pred_dt` (from-class-sized, real data) | Real predictor rows for prediction | VERIFIED |

The d314504 bug fix is critical: without the int64 cast, `make_key_tbl()` produced an int32 key table that failed to match the parquet's int64 `cell_id` and silently returned no rows. The fix is present in the codebase (L2154-2156). HPC evidence confirms the fix works (bit-for-bit identical results).
