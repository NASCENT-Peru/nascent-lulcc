# Phase 1.1: Fix Dinamica Launch Contract — Context

**Gathered:** 2026-05-15
**Status:** Ready for planning
**Type:** INSERTED (Phase 1 hotfix; surfaced by 2026-05-15 live HPC verification)

<domain>
## Phase Boundary

This phase repairs the Dinamica-on-HPC launch contract that Phase 1 shipped but never end-to-end-validated against a built `.sif` on Euler. Live verification on 2026-05-15 (eu-login-18, apptainer 1.4.5, freshly built `dinamica-ego-8.sif`) exposed seven independent structural failures in the path that runs from `scripts/run_allocation.r` → `src/dinamica_utils.r:resolve_dinamica_launch()` / `exec_dinamica()` → `apptainer exec ... DinamicaConsole ...`. The container itself works; the launch command, smoke-test fixture, error-detection contract, container `.def` bootstrap, and env-install fallback are all broken in ways that prevent any allocation worker from completing on Euler. This phase lands the six remediations enumerated in `.planning/phases/01-repair-visibility/01-HUMAN-UAT.md` so INFRA-01 / SC6 can finally close.

The phase is scoped to Stage 7 Dinamica wiring + the Phase 1 env-bootstrap contract. It does NOT change Stage 7 modelling logic, the allocation algorithm, or any pipeline stage outside Phase 1's footprint. After this phase, a fresh operator on Euler should be able to run `bash scripts/setup_environments.sh --env allocation_env --non-interactive` and `bash scripts/smoke_test_dinamica.sh --live ...` to a green light, against a `.sif` rebuildable from this repo without manual workstation transfer.

</domain>

<decisions>
## Implementation Decisions

### Container Build Provenance (G1)
- **D-101:** Rewrite `dinamica/container/rocker-geospatial-dinamica.def` to bootstrap from a publicly-pullable image (`docker://rocker/r-ver:4.5.3` or `docker://rocker/geospatial:4.5.3`) and inline the upstream Dockerfile's Dinamica steps in `%post` (download AppImage from `dinamicaego.com/nui_download/1960/`, `--appimage-extract`, copy `squashfs-root/` to `/opt/dinamica`). The current `From: ghcr.io/ethzplus/rocker-geospatial-dinamica:latest` references an image that was never published — upstream is a Dockerfile-only repo because Dinamica's licence forbids redistribution. This is the only sustainable bootstrap; the `docker save` → `docker-archive://` workstation-transfer dance is a one-time workaround, not a contract.
- **D-102:** Pin the upstream base image tag (`rocker/r-ver:4.5.3`) and the AppImage download URL by version, not by `:latest`, so rebuilds are byte-reproducible. Document the rebuild trigger conditions in `dinamica/container/README.md`.
- **D-103:** The built `.sif` remains an external artifact (D-10 unchanged). What changes is that `apptainer build dinamica-ego-8.sif dinamica/container/rocker-geospatial-dinamica.def` actually works on Euler with no extra steps.

### Launch Command Shape (G3, G4, G6)
- **D-104:** `src/dinamica_utils.r:resolve_dinamica_launch()` MUST build the apptainer launch as `apptainer exec --home <staged-home> --env DINAMICA_EGO_8_TEMP_DIR=<staged-tmp> <sif> bash -c 'cd /opt/dinamica/usr && bin/DinamicaEGO.sh <abs-model-path>'`. Direct `apptainer exec <sif> DinamicaConsole <model>` invocation is unsupported by the upstream image and produces silent `std::exception` failures; the `bin/DinamicaEGO.sh` launcher is the only entrypoint that sets the env vars (`PROJ_DATA`, `DINAMICA_EGO_8_INSTALLATION_DIRECTORY`, `DINAMICA_EGO_8_GDAL_DATA`, `DINAMICA_EGO_8_LOG_PATH`) and relative paths the binary needs.
- **D-105:** The `<staged-home>` and `<staged-tmp>` directories live under `$HPC_SCRATCH_ROOT/dinamica-home/` and `$HPC_SCRATCH_ROOT/dinamica-tmp/` respectively. `resolve_dinamica_launch()` must create them if missing and seed `<staged-home>/.dinamica_ego_8.conf` with the same minimal content the upstream Dockerfile writes (R interpreter path, ClConfig, MemoryAllocationPolicy, RCranMirror). Local-backend invocation skips both flags.
- **D-106:** The model path passed to `bin/DinamicaEGO.sh` MUST be absolute (the launcher's relative-path branch is fragile under `cd`).

### Error Detection Contract (G2)
- **D-107:** `DinamicaConsole` returns exit code 0 even on `std::exception` and on hard parse failures (`"The .ego-decoded does not represent a supported model script format"` followed by `"terminate called after throwing an instance of 'DFF::Exception'"`). `exec_dinamica()` and `scripts/smoke_test_dinamica.sh` MUST grep their captured stdout/log for the strings `Dinamica EGO exited with an error`, `terminate called after throwing`, and `std::exception`, and return non-zero on any match — regardless of the subprocess exit code. This is the only way the Phase 1 SC2 contract ("operator can diagnose any allocation failure within minutes") can hold.
- **D-108:** The error-detection grep operates on the SAME log artifact that `exec_dinamica()` already writes to `logs/dinamica/<ts>_dinamica.log` (and that the smoke test writes to `logs/dinamica-smoke-<ts>.log`). No new log surface required.

### Smoke-Test Fixture (G5)
- **D-109:** Replace `dinamica/dinamica_model/allocation.ego-decoded` (which is the production allocation model AND in the wrong file format — `.ego-decoded` is the human-readable text dump that DinamicaConsole rejects) with a true minimal smoke fixture: a hand-written ~5-line `.ego-decoded` source that does nothing more than declare a constant and exit, plus its compiled `.ego` binary form. Both files committed.
- **D-110:** The smoke `.ego` binary is generated via `process_dinamica_script(mode = "encode")` (which already exists in `src/dinamica_utils.r:335-394` and round-trips text ↔ base64-encoded R/Python chunks). If `process_dinamica_script` cannot produce a true `.ego` binary that DinamicaConsole accepts, the alternative is a one-time hand-built `.ego` saved by Dinamica EGO GUI on a workstation and committed as a binary asset. Decision deferred to planning based on actually trying `process_dinamica_script` against a minimal source.
- **D-111:** The production allocation path keeps using its existing encode-then-execute flow (`run_allocation_dinamica()` already handles the `.ego-decoded` → `.ego` encode step before invocation per `src/dinamica_utils.r:411-412`). No change to the production code's view of the model file.

### Env Install Root Contract (G7)
- **D-112:** `scripts/setup_environments.sh` MUST refuse to silently fall back to `$PROJECT_ROOT/.envs` when running on HPC and `HPC_SCRATCH_ROOT` is unset. Detection signal: any of `SLURM_*` env vars set, or `/cluster/scratch` exists, or an explicit `--hpc` flag. On detection without `HPC_SCRATCH_ROOT`, exit non-zero with a single actionable message ("export HPC_SCRATCH_ROOT or source .env before running") — same shape as `scripts/hpc_common.sh --check-stage7-contract`.
- **D-113:** When the local fallback IS the right behaviour (workstation, no HPC signals), keep the current `$PROJECT_ROOT/.envs` path but emit a one-line confirmation so operators know where the env lives.

### Documentation
- **D-114:** Update `dinamica/container/README.md` and `docs/README_HPC.md` to reflect the new launch command shape (D-104) and the rebuilt `.def` (D-101). Drop the workstation `docker save` workaround from the canonical instructions; keep it only as a fallback note.

### the agent's Discretion
- **DD-1:** Choice of `rocker/r-ver:4.5.3` vs `rocker/geospatial:4.5.3` as the bootstrap base in D-101. The latter ships GDAL/PROJ pre-installed (smaller `%post` block, faster build) but pulls a larger base. Pick whichever yields a working `.sif` smaller and faster to rebuild; document the choice in the README.
- **DD-2:** Whether the new minimal smoke fixture under D-109 lives at `dinamica/dinamica_model/smoketest.ego{-decoded}` or replaces `allocation.ego-decoded`. If it replaces, `src/dinamica_utils.r` callers that currently load `allocation.ego-decoded` need updating; verify no production code path actually uses that file (the production path uses model files staged into `work_dir`, not the committed asset).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `src/dinamica_utils.r:process_dinamica_script()` (lines 335–394) already does base64 round-tripping of R/Python chunks inside `.ego` files. Whether it can also produce a binary `.ego` from a hand-written `.ego-decoded` source is the open question that decides D-110.
- `src/dinamica_utils.r:resolve_dinamica_log_path()` (lines 587–606) already centralizes Dinamica logfile placement; reuse it as the grep target for D-107's error detection.
- `src/utils.r:log_msg()` and `worker_state_*` API (lines 1016–1163) are unchanged by this phase — the SENTINEL/diagnose contract was already proven by the workstation fixture.
- `scripts/hpc_common.sh:check_stage7_contract()` is the model for D-112's HPC-detection refusal in `setup_environments.sh`.

### Established Patterns
- The single-entrypoint discipline (`exec_dinamica()` is the only Dinamica caller-facing function) MUST be preserved — D-104's launch-shape change happens entirely inside `resolve_dinamica_launch()` so no caller signatures shift.
- Pre-flight gates fail fast with one consolidated message — D-112 follows the same shape for env-install refusal.
- External artifacts (D-10 — `.sif` lives outside repo) stay external; this phase only changes how the artifact is *built*, not where it lives.

### Integration Points
- `scripts/run_allocation.r` calls `exec_dinamica()` indirectly through `run_allocation()` → `run_allocation_dinamica()`. None of those call sites need to change — the launch-shape fix is internal to `resolve_dinamica_launch()`.
- `scripts/smoke_test_dinamica.sh` is a standalone script that must mirror the launch shape `resolve_dinamica_launch()` produces. Risk: drift between R-side and shell-side launch contracts. Mitigation: the planning step should consider extracting the launch command construction into a shared shell helper that both sides source, or at minimum codify the command shape in one canonical comment block both files reference.

</code_context>

<specifics>
## Specific Ideas

- The fix to `resolve_dinamica_launch()` should produce, for HPC backend, a single `bash -c '...'` payload rather than a multi-arg apptainer command. This keeps the cd + launcher invocation atomic and avoids quoting hazards when the model path contains spaces.
- The smoke-test script's new exit code 5 ("Dinamica printed an error string but returned 0") should be documented alongside the existing 0/1/2/3/4 contract at `scripts/smoke_test_dinamica.sh:38-44`.
- The new `.def` should retain the `%test` block, but make its assertion something Dinamica actually supports (e.g. `bash -c 'cd /opt/dinamica/usr && bin/DinamicaEGO.sh /opt/dinamica/usr/share/smoketest.ego'` — staging the smoke fixture INSIDE the container guarantees the build itself proves end-to-end-runnability).
- After this phase lands, re-run the same three live HPC tests from `01-HUMAN-UAT.md` (smoke test, env solve, SLURM OOM probe) to close out the deferred Test 3 and confirm INFRA-01 / SC6 holds.

</specifics>

- Migrating away from upstream `ethzplus/rocker-geospatial-dinamica` entirely (e.g. building Dinamica from source or wrapping it differently). Out of scope; D-101 still bootstraps from the same upstream Dockerfile logic, just inlined.
