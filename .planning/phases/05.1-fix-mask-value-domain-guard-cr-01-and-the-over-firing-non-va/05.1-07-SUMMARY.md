# Phase 05.1 Plan 07: The D-03 cross-file wording contract, made self-enforcing Summary

The frozen wording that makes a bad intervention mask fatal is now asserted over the R
parser's view of the three files that must agree on it — the verifier's **evaluated**
`forbidden` vector and each emitter's **string literals** — so paraphrasing a message or
deleting a `forbidden` entry while a comment keeps quoting the old text breaks a test
instead of passing silently (R51-IN-05).

## What was built

### `tests/testthat/helper-intervention-contract.R` (new, 9 top-level expressions, all function definitions)

| Function | What it does |
|---|---|
| `.contract_string_literals(path)` | `parse(keep.source = TRUE)` → `utils::getParseData()` → `pd$text[pd$token == "STR_CONST"]`, each token re-parsed so `\"` / `\\` read as the characters they denote. The parser discards comments and emits `STR_CONST` only for string literals, so a comment can never appear in the result. |
| `.contract_forbidden_vector(path)` | Finds the single top-level `forbidden <- ...`, requires its RHS to be `c()` with every argument a length-1 character literal, then lifts the expression by `attr(exprs, "srcref")` and `eval(parse(text = <that text>), envir = new.env(parent = baseenv()))`. The empty `baseenv()`-parented env means any variable the block referenced would error rather than resolve. |
| `.contract_missing(literals, substrings)` | The substrings present in NO literal; `character(0)` when all are present. |
| `.contract_literals_with(literals, substring)` | The literals carrying `substring`. |
| `.contract_path(...)` | `file.path(.repo_root, ...)`, resolved at CALL time (helpers load alphabetically, so this file loads *before* `helper-spatial-interventions.R`). |
| `.contract_mark()` / `.contract_stem()` | The single spelling of `"intervention mask: "` and `"intervention mask "`. |
| `.engine_form_ok(lits, s, mark, stem)` | The colon-FREE rule: `s` occurs, every literal carrying it contains `stem`, none contains `mark`. |
| `.preflight_form_ok(lits, s, mark)` | The colon rule: `s` occurs and every literal carrying it `startsWith(mark)`. |

The two predicates are one implementation shared by the real assertions (blocks 2, 3) and
by their proof (block 12), so the proof cannot drift from the rule it proves.

`has no cell equal to 1` → `has no 1-coded cell`, then a line `# has no cell equal to 1` is

- `grepl(.S3, <whole mutated text>, fixed = TRUE)` is **TRUE** — **the retired CR-01s grep

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Block 8's "the old grep stays green" assertion was false and failed**
- **Found during:** Task 2, first run of the appended non-vacuity section.
- **Issue:** The plan's uniform framing ("the whole-text grep would still pass") does not hold
  for the split-literal case. `x <- c("has no cell ", "equal to 1")` does **not** contain
  `has no cell equal to 1` contiguously — the `", "` sits between the halves — so a whole-text
  grep is red there too. The literal transcription of that assertion produced a real failure:
  `blocks: 12 expectations: 67 failed: 1`, block 8.
- **Fix:** Replaced it with the check that *is* fooled by a split literal — pasting every
  string literal of the file into one blob, `grepl(.S3, paste(lits, collapse = ""))`, is TRUE
  while `.contract_missing()` still reports `.S3` missing. Out-of-band probe H3 confirms that
  this is a real alternative implementation and that block 8 goes RED under it.
- **Files modified:** `tests/testthat/test-intervention-wording-contract.R`
- **Commit:** `598b7b4`

### Mechanics / sequencing decisions (no user input needed)

**2. `.engine_form_ok()` / `.preflight_form_ok()` landed in task 1, not task 2.**
  The plan asked for them in task 2 with blocks 2 and 3 refactored onto them afterwards.
  Writing them up front and having blocks 2/3 use them from the start reaches the same end
  state (one shared implementation for rule and proof) without a churn commit that rewrites
  code added minutes earlier. Both are in `helper-intervention-contract.R` as specified.

**3. The markers are exposed as `.contract_mark()` / `.contract_stem()` functions.**
  The plan's acceptance criterion requires the helper to contain "no top-level call other
  than function definitions", which rules out a top-level `.MARK <- "..."` constant. Accessor
  functions keep that property while still giving the two spellings a single home; they are
  the defaults of the two predicates, and block 1 asserts `identical(.MARK, .contract_mark())`
  and `identical(.STEM, .contract_stem())` so the test file's constants cannot drift from the
  rule's.

**4. `<verify>` blocks were executed from scratchpad `.R` files rather than as `Rscript -e`.**
  Two documented host constraints forced this and nothing was weakened: on this machine
  `Rscript -e` strips one backslash level (so an embedded `\\s` arrives as `\s`), and the
  sandbox's git-safety filter refuses inline `Rscript -e` whose program text can start another
  program. Each verify's R code was written verbatim to a file in the session scratchpad and
  run with `Rscript <path>`; the stopifnot() conditions are unchanged. Both plan verifies
  printed `ok`.

**5. Two extra proof probes were run beyond the plan.** The plan's non-vacuity requirement is
  satisfied in-suite by blocks 6-12. Probes 1 and 2 above were added so the SUMMARY can report
  observed RED for every mutation class rather than asserting it; they live only in the session
  scratchpad and changed no repository file.

## Assumption Drift (advisory)

**A split literal is caught by a whole-text grep too.**
- **Found during:** Task 2, block 8.
- **Planned:** the plan's prose and block-8 spec treat all five non-vacuity classes as cases
  where "the old whole-text grep stays green while the parse-based check goes red".
- **Actual:** that framing is true for the comment classes (6, 7) and for the mutated real
  files (10, 11), but false for the split literal: the frozen substring is not contiguous in
  the source text, so a whole-text grep also rejects it. The naive check a split literal
  defeats is one that concatenates all string literals.
- **Why it matters:** a reader comparing the plan's claim with the committed block would
  otherwise think the block had been weakened. It has not; it pins a different, real
  alternative implementation (confirmed red under probe H3).
